# План ручной визуальной проверки

Этот план относится к визуальному редизайну доски проектов (`redesign-project-board-ui`). Он дополняет автоматические тесты, а не заменяет их: `npm run test:production` проверяет операции и сохранность данных, а здесь проверяются реальные размеры, визуальная и keyboard-подача интерфейса.

## Область проверки

Используйте сценарии ниже как каталог для выборочной проверки по [правилу просмотра скриншотов](../AGENTS.md#выборочный-просмотр-скриншотов). Выбирайте экраны, размеры, языки и состояния по изменению интерфейса, конкретной визуальной ошибке или запросу пользователя. При изменении адаптивной вёрстки проверяйте затронутые desktop/mobile-размеры; дополнительные снимки открывайте для нерешённых вопросов. Явные визуальные критерии приёмки выполняйте в заданной области.

Успешный автоматический прогон без изменений UI не требует открытия PNG, прохождения всего чек-листа или отдельного визуального отчёта. Визуальная проверка подтверждается фактическим просмотром, а не наличием снимков или успехом тестов. После выполненного просмотра укажите проверенные экраны, размеры, языки, состояния, результат и существенные ограничения. Основной чат может использовать этот отчёт без повторного просмотра тех же снимков при отсутствии новой причины.

## Подготовка

1. Запустите приложение через `npm run dev` либо откройте опубликованную версию.
2. Используйте отдельный профиль браузера, окно инкогнито или тестовое устройство. Не очищайте IndexedDB с личными данными ради этой проверки.
3. Выберите относящиеся к области проверки viewport в актуальном Chrome:
   - desktop — `1280 × 900` или шире;
   - mobile narrow — `320 × 568`;
   - mobile regular — `390 × 844`.
4. Для сценариев с заполненной доской создайте тестовый проект «Manual QA», статусы «Идеи», «В работе», «Завершено» и хотя бы одну карточку в «Идеи».

## Примечание о storage error

В обычном пользовательском интерфейсе нет кнопки, которая намеренно ломает IndexedDB или сохранение. Не отключайте хранилище и не удаляйте реальные данные ради этого сценария. Сейчас S-01 подтверждён автоматическими RTL-тестами; ручную часть выполняйте только в отдельном тестовом профиле, если есть безопасный способ воспроизвести ошибку.

## Визуальный чек-лист

- Кнопки-иконки и основные touch controls имеют фактический размер не меньше `44 × 44 px` (при сомнении проверьте размер в Chrome DevTools).
- Акцентный teal применяется к основному действию и focus state, а не кодирует смысл статусов.
- Текст, ошибка и disabled action различимы без опоры только на цвет.
- На заполненных каталогах и досках нет постоянно раскрытых технических форм.
- Отступы, радиусы и тени согласованы: поверхности border-first, тень только у приподнятых/интерактивных карточек.
- Нет новых фильтров, «completed»-семантики или других функций за пределами согласованной модели. Drag-and-drop дополняет доступное меню перемещения и не заменяет его.

## Страница карточки, описание и личные заметки

- Открыть карточку по названию, метке, свободной площади и Enter; отдельное верхнее меню не открывает страницу; начатый drag и его отмена также не открывают её. «Редактировать» ведёт на ту же страницу.
- Проверить прямой адрес карточки, перезагрузку и «Назад к доске»; чужая карточка и удалённые сущности не раскрывают данные.
- Сохранить/очистить описание, независимо добавить и исправить заметку; no-op не меняет дату, удаление требует подтверждения с текстом, отмена возвращает фокус.
- Проверить RU/EN, 320/390/1280 px, длинные ссылки и многострочный текст; HTML/Markdown отображаются текстом, только HTTP/HTTPS открываются отдельно.
- При dirty полях/заметке проверить бренд, возврат, Back/Forward, быстрые повторные Back и переключение редакторов: один диалог с тремя решениями. Ошибка второго сохранения оставляет первую часть подтверждённой и заметку доступной без дубликата.
- Проверить управляемое обновление PWA через guard и стандартный beforeunload только при dirty. Нативное закрытие не обещает сохранение; forced restart после versionchange не записывает через закрытую базу.
- Перенести карточку, повторно открыть офлайн и проверить описание/заметки/даты.

## Удаление проекта

- Откройте меню проекта в каталоге и «Удалить проект». Проверьте название, количества статусов и карточек, предупреждение и доступные кнопки на RU/EN при 320/390/1280 px. Ввод названия не нужен. Пока сводка загружается или чтение не удалось, удаление недоступно; чтение можно повторить или отменить.
- На доске запустите удаление из настроек: панель закрывается, начальный фокус на «Отмена», Escape возвращает к шестерёнке. В настройках каталога, страницы карточки и служебных экранов удаления нет.
- Удалите проект с карточками и заметками: остальные проекты и порядок сохраняются. Из каталога фокус переходит к следующему, предыдущему либо созданию проекта; с доски открывается каталог и фокусируется создание.
- Проверьте старую ссылку доски/карточки, Back/Forward и перезагрузку офлайн: удалённое содержимое не возвращается. После последнего проекта видно пустое состояние.
- В отдельном тестовом профиле проверьте отказ транзакции: всё содержимое и последнее открытие сохраняются, подтверждение остаётся для повтора. Отказ чтения после успешной записи показывает недоступность хранилища и не предлагает повторно удалить проект.

## Установка EasyTrack

- В чистом профиле (без данных сайта) откройте приложение в RU и EN при 320, 390 и 1280 px: при первом входе открывается приглашение «EasyTrack можно установить» с инструкцией для платформы и объяснением локального хранения, без горизонтальной прокрутки. На iPhone/iPad (включая iPad в режиме настольного сайта) инструкция «Поделиться» предупреждает, что проекты из Safari не переносятся.
- Закройте приглашение без флажка «Больше не показывать» и перезагрузите страницу: приглашение появляется снова. С флажком оно больше не появляется, а в настройках остаётся пункт «Как установить EasyTrack».
- В Chrome, когда браузер предлагает установку, пункт настроек и открытое приглашение показывают «Установить EasyTrack» и открывают нативный диалог. Плавающей кнопки установки нет ни на доске, ни в панели карточки, ни в каталоге.
- В установленном приложении приглашение не открывается; пункт настроек «Где хранятся проекты» объясняет локальное хранение.

## Card panel

Check panel, page and confirmed board-description preview in RU/EN at 320/390/1280 px. On narrow screens the panel fills the screen, Tab/Shift+Tab cycle within it, and board and update controls are inert; nested draft/deletion confirmations remain reachable. On desktop the board stays interactive beside the panel, with independent scrolling and distinguishable region names. Open a card well down a long board and check that the same board-main scroll container retains its position during panel open, page expansion, Back and close. Check A → B → C → Back restores the board and focus to C without resetting scroll. Enter fields and a note, expand, and verify both drafts survive without a guard dialog. Save then Back to the panel. Direct/new-tab/reloaded addresses open a page; the board-return action has an arrow and project name before the form. Verify description previews never show drafts, note edit/delete icons retain accessible names, and destructive board actions ask the draft guard before confirmation. Native unload uses the browser warning; a forced stale-DB restart cannot guarantee draft persistence or write through the closed connection.

Результат 2026-11-05 (агент, Chromium):

- N-01: снимки e2e `card-drag-ru-320` и `card-drag-en-1280` после переноса через меню и drop — уведомление внизу по центру, внутри экрана; e2e на 320/390/1280/1440 RU/EN подтверждает неизменный верх `.status-columns`, центрирование и `pointer-events: none`. Исчезновение через 4000 мс — юнит-тест.
- N-03: снимки стопки на 390 и 1280 px (RU) и всех четырёх значений `placement` на 1280 px — временное над постоянным, без наложения; `top-center` перекрывает app bar, этот вариант сейчас не используется.
- N-02 и N-04: подтверждены автоматическими тестами (`pointer-events`, `inert`/`aria-hidden`, Tab внутри диалога), вручную не проходились.
- N-05: проверено пользователем в VoiceOver на macOS 2026-11-05 — оба одинаковых результата объявлены.
