# Spec Delta

## Purpose

Позволяет просматривать и редактировать подробности карточки и историю личных заметок в панели доски или на странице по прямому адресу, сохраняя контекст работы.

## ADDED Requirements

### Requirement: Whole-card detail navigation
Система SHALL открывать подробности карточки в панели при нажатии на любую её область на доске, кроме самостоятельных контролов. Открытие SHALL быть доступно семантическим контролом с клавиатуры. Стрелки, меню и их действия SHALL работать самостоятельно без открытия подробностей.

#### Scenario: User clicks the card body
- **WHEN** пользователь нажимает на название, метку или свободную площадь карточки
- **THEN** открывается панель именно этой карточки; на широком экране доска остаётся видимой и доступной

#### Scenario: User operates card controls
- **WHEN** пользователь нажимает стрелку перемещения, область недоступной стрелки, меню или пункт меню
- **THEN** открытие карточки не происходит вследствие всплытия нажатия; доступное действие выполняет только свою операцию

#### Scenario: Keyboard user opens details
- **WHEN** пользователь фокусирует контроль открытия карточки и нажимает Enter
- **THEN** открываются её подробности, а фокус перемещается в панель

#### Scenario: User chooses editing from the menu
- **WHEN** пользователь выбирает «Редактировать» в меню карточки
- **THEN** открывается та же панель карточки с сохранёнными основными полями

#### Scenario: User switches cards from the board
- **WHEN** пользователь нажимает другую карточку при открытой панели
- **THEN** после разрешения несохранённых изменений панель показывает выбранную карточку, а доска остаётся доступной

### Requirement: Addressable card page and board return
Карточка SHALL иметь один адрес для панели и полной страницы. Открытие с доски SHALL показывать панель с возможностью перейти на полную страницу; прямое открытие адреса и перезагрузка SHALL показывать полную страницу. Обе формы SHALL предоставлять возврат к доске. Система SHALL проверять принадлежность карточки проекту и явно обрабатывать отсутствие карточки или проекта.

#### Scenario: User follows a direct address
- **WHEN** пользователь открывает адрес существующей карточки или перезагружает его
- **THEN** полная страница показывает её подтверждённые поля и заметки в контексте соответствующего проекта

#### Scenario: User opens a card from the board
- **WHEN** пользователь открывает карточку с доски
- **THEN** панель показывает подробности, адрес браузера становится адресом карточки, а исходная доска остаётся доступной рядом на широком экране

#### Scenario: User expands the panel
- **WHEN** пользователь выбирает «Открыть на всю страницу» в панели
- **THEN** те же подробности показываются на полной странице по тому же адресу с сохранением подтверждённых данных и текущих черновиков

#### Scenario: User switches several cards and goes back
- **WHEN** пользователь открывает A, затем B и C из доски и нажимает браузерное «Назад»
- **THEN** панель закрывается и отображается исходная доска без промежуточного возврата через B и A

#### Scenario: User reloads an open panel
- **WHEN** пользователь перезагружает адрес карточки при открытой панели
- **THEN** открывается полная страница этой карточки по тому же адресу

#### Scenario: User returns to the board
- **WHEN** пользователь выбирает «К доске» на странице карточки, в том числе открытой напрямую
- **THEN** после разрешения несохранённых изменений открывается родительская доска с актуальными карточками

#### Scenario: User closes the panel
- **WHEN** пользователь закрывает панель её действием закрытия или браузерным «Назад»
- **THEN** после разрешения несохранённых изменений отображается исходная доска с прежним положением прокрутки и фокусом на доступном контроле карточки

#### Scenario: User sees the board return on a narrow screen
- **WHEN** пользователь открывает страницу карточки на узком экране
- **THEN** возврат к её доске виден перед формой, не перекрывает заголовок и имеет удобную для касания область и видимый фокус

#### Scenario: Requested card is unavailable
- **WHEN** адрес ссылается на отсутствующую карточку или карточку другого проекта
- **THEN** чужие данные не показываются и доступно понятное сообщение с переходом на указанную существующую доску

#### Scenario: Requested project is unavailable
- **WHEN** проект в адресе отсутствует
- **THEN** приложение переходит к каталогу без показа карточки другого проекта

### Requirement: Card description and explicit field saving
Панель и полная страница SHALL показывать название, необязательное описание, важность и срочность и сохранять эти поля вместе кнопкой «Сохранить». Описание SHALL поддерживать многострочный текст и очистку до пустого значения. Успешное сохранение SHALL оставлять подробности открытыми и не сбрасывать черновик заметки. При ошибке введённые значения SHALL оставаться доступными.

#### Scenario: User saves all basic fields
- **WHEN** пользователь меняет название, описание и признаки и выбирает «Сохранить»
- **THEN** все поля сохраняются вместе, открытые подробности и доска отражают подтверждённые значения

#### Scenario: User saves fields while a note draft is open
- **WHEN** пользователь выбирает «Сохранить» при несохранённом черновике заметки
- **THEN** основные поля сохраняются, подробности остаются открытыми, а черновик заметки не изменяется

#### Scenario: Saving fields fails
- **WHEN** сохранить название, описание или признаки не удаётся
- **THEN** подтверждённые поля и данные доски не изменяются, а введённые поля и черновик заметки остаются доступными для повторной попытки

#### Scenario: User clears the description
- **WHEN** пользователь очищает описание и успешно сохраняет
- **THEN** описание остаётся пустым после перезагрузки без изменения заметок

#### Scenario: User changes description without changing flags
- **WHEN** пользователь сохраняет только новое описание
- **THEN** порядок карточки внутри своей группы не меняется

### Requirement: Dated personal note history
Панель и полная страница SHALL показывать отдельные заметки карточки с датами создания и позволять добавить непустую заметку самостоятельным действием. Заметки SHALL отображаться от старых к новым в стабильном порядке; даты SHALL соответствовать языку интерфейса и локальному часовому поясу. Создание заметки SHALL не сохранять и не сбрасывать черновики основных полей.

#### Scenario: User adds a note
- **WHEN** пользователь вводит многострочный текст и выбирает «Добавить заметку»
- **THEN** после сохранения заметка с датой появляется в истории, очищается только её поле ввода, а подробности остаются открытыми

#### Scenario: User submits an empty note
- **WHEN** пользователь отправляет пустой или состоящий из пробелов текст заметки
- **THEN** заметка не создаётся, форма показывает ошибку и остаётся доступной

#### Scenario: Card has no notes
- **WHEN** пользователь открывает карточку без заметок
- **THEN** история показывает понятное пустое состояние и доступно добавление первой заметки

### Requirement: Editable and confirmed deletable notes
Система SHALL позволять исправить заметку отдельным сохранением и удалить её только после подтверждения, идентифицирующего запись. У сохранённой заметки действия редактирования и удаления SHALL отображаться как иконки карандаша и корзины в стиле остальных иконок приложения, с локализованными доступными именами, удобной для касания областью и видимым фокусом. Кнопки добавления и сохранения заметки и отмены редактирования SHALL сохранять текстовые подписи. Изменение SHALL сохранять исходную дату и позицию и показывать отметку «изменено»; сохранение прежнего текста SHALL не создавать отметку. Отмена SHALL сохранять запись.

#### Scenario: User edits an existing note
- **WHEN** пользователь сохраняет изменённый непустой текст заметки
- **THEN** текст обновляется с отметкой изменения, исходной датой и прежним местом в истории

#### Scenario: User saves an unchanged note
- **WHEN** пользователь сохраняет текст без фактических изменений
- **THEN** дата изменения и отметка изменения не добавляются и не обновляются

#### Scenario: User confirms note deletion
- **WHEN** пользователь подтверждает удаление выбранной заметки
- **THEN** удаляется только эта заметка, результат сохраняется после перезагрузки, фокус остаётся на доступном контроле истории

#### Scenario: User cancels note deletion
- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** заметка остаётся без изменений

### Requirement: Plain text with usable web links
Описание и заметки SHALL сохранять многострочный обычный текст и показывать абсолютные HTTP/HTTPS ссылки как кликабельные. HTML и Markdown SHALL отображаться как текст. Открытие веб-ссылки SHALL сохранять открытые подробности и их черновики.

#### Scenario: User views multiline text and a URL
- **WHEN** сохранённый текст содержит переносы строк и абсолютную HTTPS ссылку
- **THEN** переносы сохраняются, ссылка доступна мышью и клавиатурой и открывается отдельно от карточки

#### Scenario: User saves markup or another URL scheme
- **WHEN** пользователь сохраняет HTML, Markdown или адрес javascript/data
- **THEN** содержимое не исполняется как разметка или код и опасный адрес не становится активной ссылкой

### Requirement: Guarded navigation with unsaved drafts
При несохранённых основных полях или черновике новой/редактируемой заметки система SHALL перед закрытием панели, переключением карточки, внутренним переходом, Back/Forward или управляемым обновлением приложения предлагать сохранить и выйти, выйти без сохранения или остаться. Переход после сохранения SHALL происходить только при успехе всех ожидающих сохранений.

#### Scenario: User leaves after saving drafts
- **WHEN** пользователь выбирает «Сохранить и выйти», а основные поля и заметка корректны и записаны
- **THEN** применяется исходно выбранный переход без повторного подтверждения и без дублирования заметки

#### Scenario: User discards pending changes
- **WHEN** пользователь выбирает «Выйти без сохранения»
- **THEN** только оставшиеся черновики отбрасываются и выбранный переход выполняется

#### Scenario: User keeps the current card open
- **WHEN** пользователь выбирает «Остаться», закрывает диалог или нажимает Escape
- **THEN** текущая панель или страница, значения черновиков и текущая запись навигации сохраняются

#### Scenario: User switches cards with a draft
- **WHEN** пользователь нажимает другую карточку на доске при несохранённых полях или заметке в панели
- **THEN** до переключения система предлагает три действия; выбор «Остаться» сохраняет прежнюю карточку и черновики, а ошибка сохранения не показывает другую карточку

#### Scenario: Saving only partly succeeds
- **WHEN** при «Сохранить и выйти» основные поля записаны, но сохранить заметку не удалось
- **THEN** переход не выполняется, поля остаются подтверждёнными, текст заметки остаётся черновиком с ошибкой и доступной повторной попыткой без дубликатов

#### Scenario: User switches note editors
- **WHEN** пользователь начинает другую заметку при несохранённом тексте текущей
- **THEN** текущий черновик защищён тем же выбором перед переключением

#### Scenario: User reloads or closes the browser
- **WHEN** пользователь пытается нативно перезагрузить открытые подробности или закрыть вкладку с черновиком
- **THEN** приложение запрашивает стандартное браузерное предупреждение, если браузер его поддерживает, без обещания сохранения при закрытии

#### Scenario: User activates an app update
- **WHEN** пользователь выбирает обновление приложения при наличии черновиков
- **THEN** управляемая активация и перезагрузка ждут решения guard; отмена или ошибка сохранения оставляет текущую панель или страницу

### Requirement: Local durable note operations and failures
Описание, заметки и их даты SHALL сохраняться локально, работать офлайн и не меняться при переносе карточки. При ошибке операции заметки подтверждённые данные SHALL оставаться прежними, введённое SHALL сохраняться для повторной попытки и успех SHALL не объявляться.

#### Scenario: User returns offline
- **WHEN** пользователь сохраняет описание и заметки, повторно открывает установленное приложение без сети
- **THEN** сохранённые данные доступны и новые локальные изменения можно сохранить

#### Scenario: User moves a detailed card
- **WHEN** пользователь переносит карточку в другой статус
- **THEN** описание, заметки и даты сохраняются у той же карточки

#### Scenario: A note operation fails
- **WHEN** создание, изменение или удаление заметки не удаётся записать
- **THEN** история остаётся в последнем подтверждённом состоянии, редактор/подтверждение остаётся доступным с введённым текстом и сообщением об ошибке

### Requirement: Accessible localized detail page
Панель, полная страница и диалоги SHALL быть доступны с клавиатуры и на ширине 320 px, иметь подписанные поля, видимый фокус и русские/английские подписи и ошибки. На узком экране подробности, открытые с доски, SHALL занимать экран целиком. Длинные тексты и ссылки SHALL не перекрывать действия и не создавать горизонтального переполнения. Пользовательский текст SHALL не переводиться.

#### Scenario: User works on a narrow screen in English
- **WHEN** пользователь открывает карточку с длинными текстами при английском интерфейсе на ширине 320 px
- **THEN** поля, история, ссылки, даты и действия доступны и читаемы без горизонтального scroll страницы, подписи и ошибки английские

#### Scenario: User interacts with confirmation using a keyboard
- **WHEN** пользователь открывает подтверждение удаления или ухода с черновиком
- **THEN** фокус входит в диалог и остаётся внутри него, а отмена возвращает его к вызвавшему действию

#### Scenario: User opens details on a narrow screen
- **WHEN** пользователь открывает карточку с доски на узком экране
- **THEN** подробности занимают весь экран, действия закрытия и сохранения доступны, а доска остаётся доступной после закрытия

#### Scenario: Keyboard user works with the panel and board
- **WHEN** пользователь открывает панель с клавиатуры, сохраняет поля и возвращается к доске
- **THEN** фокус последовательно попадает в панель и возвращается к доступному контролу карточки; доска и панель имеют различимые названия областей
