# EasyTrack — трекер личных проектов

Пет-проект для изучения полного цикла разработки с AI-инструментами и SDD на примере OpenSpec: от product discovery до опубликованных веб- и мобильных приложений.

Продукт помогает видеть этапы личных дел, сохранять договорённости и следующие шаги в заметках. Первый проверочный сценарий — поиск квартиры.

## Текущее состояние

Реализованы каталог проектов, доска статусов и карточки с локальным хранением в IndexedDB. EasyTrack можно установить как PWA; после первой онлайн-загрузки приложение повторно открывается и сохраняет локальные изменения без сети.

## Первая версия

Личное веб-приложение с несколькими проектами, досками статусов и карточками. Карточки содержат текст, ссылки, и историю заметок; следующий шаг и срок записываются в заметке.

После первоначальной загрузки приложение должно работать без интернета. В MVP предусмотрены ручная резервная копия и восстановление. Подробные границы и условия готовности описаны в vision.

Использование установленного приложения с телефона обязательно. Проверяются актуальный Chrome на компьютере, реальных iPhone и Android, а также Safari на реальном iPhone; фактические версии записываются для каждого выпуска.

## Подход к разработке

- GitHub — основной репозиторий и история проекта.
- Небольшие изменения с проверяемым поведением.
- Спецификации и предложения изменений хранятся в репозитории и ведутся с помощью OpenSpec.
- ADR создаются для значимых и труднообратимых технических решений.

Первое изменение OpenSpec описывает публикацию минимального каркаса на GitHub Pages. Значимые технические решения фиксируются в `docs/adr/`; последующие продуктовые возможности ещё не реализованы.

## Локальный запуск

Требуется Node.js 24 LTS (версия указана в `.nvmrc`).

```bash
npm ci
npm run dev
```

Production-сборку можно проверить локально:

```bash
npm run build
npm run preview
```

Vite собирает приложение для пути `/tracker/`, поэтому локальный preview открывается по адресу, который выводит команда (обычно `http://localhost:4173/tracker/`).

## Установка и локальные данные

EasyTrack можно установить как самостоятельное приложение после первой онлайн-загрузки. В Chrome и совместимых браузерах используйте пункт установки приложения; на iPhone и iPad — **Поделиться → На экран «Домой»**.

Данные остаются локальными для браузера или установленного приложения. Они не синхронизируются между устройствами и могут быть удалены при очистке данных сайта. На iPhone/iPad установленный EasyTrack имеет отдельное хранилище от Safari: проекты, созданные в Safari до установки, не переносятся автоматически. Устанавливайте приложение до создания первых важных проектов. Установка не заменяет резервную копию: в настройках («шестерёнка») можно выгрузить все данные в файл и восстановить их из него с полной заменой текущих данных. Так проекты, созданные в Safari, переносятся в установленное приложение: выгрузите копию в Safari, установите приложение и восстановите её там. Резервную копию нужно делать вручную; автоматической копии нет.

Тестовые резервные копии для ручной проверки восстановления создаёт `npm run fixtures:backup` в `fixtures/backup/`: `edge-cases.json` (длинные тексты, 15 колонок, до 200 заметок), `volume.json` (2000 карточек, 10000 заметок) и `rejected-*.json`, которые восстановление должно отклонить.

## Публикация на GitHub Pages

Агент отправляет готовую ветку и создаёт PR в `main`. После обязательной проверки `check` PR сливается методом squash без нового запроса разработчику: через GitHub auto-merge, если включена настройка **Allow auto-merge**, либо агентом после результата CI. Workflow `deploy-pages.yml` затем автоматически собирает `dist`, публикует его на `https://seraflab.github.io/tracker/` и проверяет адрес после deploy. Источник Pages — **GitHub Actions** в **Settings → Pages → Build and deployment → Source**.

## Проверка доски проектов перед релизом

Перед первым локальным PWA gate после `npm ci` установите Chromium для Playwright, затем запустите полный набор проверок:

```bash
npx playwright install chromium
npm run check
```

Если проверки запускаются параллельно в нескольких рабочих деревьях, задайте каждому свой порт: `E2E_PORT=4391 npm run check`. Занятый порт приводит к явной ошибке, а не к подключению к чужому серверу. При сбое trace и отчёт лежат в `test-results/` и `playwright-report/` (`npx playwright show-report`); в GitHub Actions — в артефакте `browser-diagnostics-<run>-<attempt>`. Порядок разбора — в [правилах тестирования](docs/agents/rules/testing.md) и [отчёте о стабильности тестов](docs/agents/test-reliability.md).

`npm run check` создаёт production-сборку и выполняет архитектурные, unit/RTL и browser-level проверки, включая сценарий двух проектов, изменения порядка статусов, переименования и переноса карточки, повторное открытие доски, offline reopen и подтверждаемое обновление.

После публикации пройдите следующий чеклист на GitHub Pages:

1. Откройте приложение на узком экране или в эмуляции мобильного устройства. Убедитесь, что отображается пустой каталог и доступно создание проекта.
2. Создайте проект «Поиск квартиры», затем статусы «Найдено» и «Договорились о просмотре». Убедитесь, что второй статус добавлен справа, а кнопка перемещения влево меняет их порядок.
3. В «Найдено» создайте карточку «Квартира у парка», переименуйте её в «Квартира с балконом» и перенесите в «Договорились о просмотре». Убедитесь, что карточка исчезла из исходного статуса и добавилась в конец целевого.
4. Создайте второй проект «Паспорт». Проверьте, что в нём не видны статусы и карточки проекта «Поиск квартиры», затем вернитесь в первый проект через каталог.
5. Перезагрузите страницу. Убедитесь, что снова открыта последняя выбранная доска, а проекты, порядок статусов и карточка сохранены.
6. На узком экране прокрутите доску по горизонтали и убедитесь, что у каждой колонки доступны создание, переименование, изменение порядка и перенос карточки через обычные элементы формы — без drag-and-drop.
7. Если какой-либо шаг не проходит, зафиксируйте браузер, устройство, URL и наблюдаемое поведение в issue до закрытия change.

Для PWA после первой онлайн-загрузки установите EasyTrack, создайте тестовый проект, закройте приложение, отключите сеть и откройте его снова. Убедитесь, что проект доступен, изменение сохраняется после ещё одного офлайн-перезапуска, а внешние ссылки без сети не обещают доступности.

### Удаление проектов

Откройте меню проекта в каталоге или настройки его доски и выберите «Удалить проект». Подтверждение показывает название и количество статусов и карточек. Удаление окончательно убирает проект со всеми статусами, карточками и заметками, в том числе офлайн; восстановления нет. После удаления открытой доски появится каталог, а после последнего проекта — его пустое состояние. Остальные проекты сохраняются.


## Агентный навык EasyTrack

Репозиторий содержит [`$easytrack`](.agents/skills/easytrack/SKILL.md) для работы с карточками через native WebMCP в поддерживаемом внутреннем браузере. Установка skill не подтверждает готовность task-интеграции: агент сначала проверяет фактически зарегистрированные инструменты, сессию и состояние хранилища. Обычный stdio MCP-сервер для этого workflow не требуется.

В чате этого проекта вызовите `$easytrack` и попросите показать проекты. Для чатов с другой рабочей папкой и пользовательского walkthrough следуйте [инструкции подключения](docs/agents/easytrack-skill.md). Репозиторий не устанавливает пользовательские навыки, не меняет глобальные настройки и не создаёт новые чаты автоматически.
