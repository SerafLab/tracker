# oxlint и stylelint вместо ESLint

Проект использует TypeScript 7.0, а typescript-eslint поддерживает TypeScript `>=4.8.4 <6.1.0`, поэтому ESLint не может выполнять правила с учётом типов, ради которых нужен линтер: потерянные промисы в потоках IndexedDB и перетаскивания, утечки `any`. 16 ноября 2026 года выбран oxlint с `oxlint-tsgolint` для TS/TSX/JS и stylelint с `stylelint-config-recommended` для CSS. tsgolint строит типы на компиляторе TS 7, поддерживает правила хуков и React Compiler, а прогон по `src` занимает около секунды. Набор правил ограничен ловлей ошибок: категория `correctness`, правила промисов и `no-unsafe-*`; стилевых правил нет. Типы проверяет отдельный шаг `tsc -b` с теми же tsconfig-проектами, что и у tsgolint.

Отвергнуты ESLint с typescript-eslint на параллельном `typescript@6` через псевдоним npm — два компилятора с риском расхождения в выводе типов — и Biome: его правила промисов экспериментальные и работают на собственном выводе типов, а не на компиляторе; для CSS он стал бы третьим инструментом с меньшим набором правил. Цена выбора: oxlint реализует не все правила typescript-eslint с учётом типов и не проверяет причину у своих отключений правил, поэтому это проверяет ревью. `oxlint-tsgolint` поддерживает конкретную версию TS 7, поэтому `typescript` и `oxlint-tsgolint` обновляются вместе.
