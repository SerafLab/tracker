# Proposal

## Why

Проект пока существует только как согласованный план, поэтому невозможно проверить полный путь от исходного кода до публичной веб-версии. Небольшой первый change должен подтвердить, что базовый React-проект действительно автоматически публикуется по постоянному адресу GitHub Pages и что опубликованная сборка доступна пользователю.

## What Changes

- Создать минимальное React, TypeScript и Vite-приложение, которое отображает идентифицируемую стартовую страницу трекера.
- Настроить production-сборку для проектного пути `/tracker/` и исключить требования к серверному fallback.
- Добавить GitHub Actions workflow, который после push в `main` собирает приложение и публикует один каталог `dist` в GitHub Pages.
- Добавить автоматическую smoke-проверку опубликованной версии: доступность выбранного Pages URL и загрузка ожидаемого app shell.
- Зафиксировать воспроизводимые локальные команды для установки зависимостей, сборки и предварительного просмотра production-сборки.
- Вести реализацию change в отдельной feature-ветке и доставлять её в `main` через pull request.

## Capabilities

### New Capabilities

- `published-web-app`: публикация минимального веб-приложения по постоянному GitHub Pages URL и проверяемая доступность опубликованной сборки.

### Modified Capabilities

Нет.

## Impact

- Новый каркас приложения и конфигурация Vite, TypeScript и npm lockfile.
- Новый GitHub Actions workflow и настройки публикации GitHub Pages.
- Новая публичная статическая сборка по `https://seraflab.github.io/tracker/`.
- Рабочая ветка `feature/bootstrap-github-pages-deployment`, pull request и merge в `main`.
- Пользовательские функции трекера, IndexedDB, service worker, офлайн-режим, резервные копии, CI для pull request и защита ветки не входят в этот change.
