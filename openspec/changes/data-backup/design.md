# Design

## Context

- Данные проектов лежат в Dexie v3: `projects`, `statuses`, `cards`, `notes`, `workspace` (`lastProjectId`). Позиции статусов проекта и карточек статуса идут подряд с нуля. Карточки внутри статуса упорядочены по группам (`domain/order.ts`). Настройки устройства хранятся в `localStorage`.
- Слои фичи проверяет `scripts/check-architecture.mjs`. Dexie доступен только инфраструктуре. Код вне фичи импортирует только `features/project-board/index.ts`. Zod уже используется в `src/app/webmcp`.
- Меню шестерёнки (`src/ui/app-bar.tsx`) принимает одно общее действие приложения через `SettingsEntryContext`. Сейчас это установка, её задаёт `InstallProvider`.
- `WorkspaceApp` (`src/app/app.tsx`) владеет защитой черновиков (`requestLeave`) и навигацией (`navigate`). Store сериализует записи интерфейса и агента флагами `agentPending`/`pendingUiWrites`.
- Версии приложения и SHA в сборке пока нет.

## Goals / Non-Goals

**Goals:**
- Одна чистая функция разбора копии: «текст → корректная копия текущей версии или причина отказа». Она проверяется unit-тестами без браузера.
- Атомарная замена в одной Dexie-транзакции, которая не пересекается с записями интерфейса и агента.

**Non-Goals:**
- Ограничение размера файла и потоковый разбор: личные данные укладываются в память.
- Шифрование и подпись копии.
- Изменение схемы IndexedDB: версия Dexie остаётся 3.

## Decisions

1. **Формат v1.**
   ```json
   { "format": "easytrack-backup", "formatVersion": 1, "exportedAt": "<ISO UTC>",
     "app": { "version": "0.1.0", "commit": "abc1234" },
     "data": { "projects": [], "statuses": [], "cards": [], "notes": [] } }
   ```
   Записи `data` повторяют доменные типы `Project`, `Status`, `Card`, `Note` один к одному. Нормализованные таблицы проще проверять и вставлять `bulkAdd`, чем вложенное дерево. JSON записывается с отступом 2: так файл можно прочитать глазами. `workspace` в копию не входит.
   - Альтернатива — вложенное дерево «проект → статусы → карточки → заметки». Оно читается чуть лучше, но требует разворачивания при вставке и не даёт выигрыша в проверке.

2. **Разбор в два шага: конверт, затем версия.** В `application/backup.ts`:
   - Шаг 1: `JSON.parse` и мягкая Zod-схема конверта `{ format: literal, formatVersion: int ≥ 1 }`. Ошибка разбора → `invalid`. `formatVersion > CURRENT` → `newer`.
   - Шаг 2: строгая схема своей версии (`z.strictObject`). Затем цепочка `migrations[v]: (v) → v+1` до текущей версии. Затем проверка целостности.
   - Так «более новая версия» распознаётся до строгой схемы, а прежние версии проходят только вперёд. Сейчас версия одна, `migrations` пуст. Тест фиксирует, что каждая версия до текущей имеет миграцию.
   - Альтернатива — одна схема с `discriminatedUnion` по версии. Она не отличает будущую версию от мусора без отдельной проверки, так что выигрыша нет.

3. **Целостность — чистая доменная функция** `checkBackupIntegrity(data)` в `domain/backup.ts`. Она проверяет уникальные ID в каждой таблице, ссылки на владельцев, позиции подряд с нуля по владельцу, невозрастающий `cardPriority` по позиции в статусе, непустые имена после `trim` и корректные ISO-даты. Порядок групп переиспользует `cardPriority`. Ничего не исправляется: см. спецификацию.

4. **Порт репозитория:** `snapshot(): Promise<BackupData>` (одна read-транзакция по четырём таблицам) и `replaceAll(data): Promise<void>` (одна rw-транзакция по пяти таблицам: `clear` всех, затем `bulkAdd`; `workspace` остаётся пустым). Исключение внутри транзакции откатывает её целиком: это стандартное поведение Dexie и IndexedDB, тест имитирует сбой `bulkAdd`.

5. **Use cases** `exportBackup()` → объект копии с `exportedAt = now()` и `app` из зависимости `build`, `summary()` → текущие числа, `parseBackup(text)`, `restoreBackup(backup)`. Версию сборки передаёт приложение через зависимости `createProjectBoardUseCases({ build })`, поэтому глобальные переменные в фиче не нужны.

6. **Сериализация в store.** Действие `restoreBackup` проверяет те же условия, что и обычные записи (`canMutate`, нет `agentPending`, `placementPending`, `pendingUiWrites`). Пока оно выполняется, флаг блокирует новые записи. Команда агента в это время получает существующий `conflict`. После успеха store сбрасывает кеш доски и карточки.

7. **Версия сборки.** В `vite.config.ts` и `vitest.config.ts` один общий помощник задаёт `define`: `__APP_VERSION__` из `package.json` и `__APP_COMMIT__`. SHA берётся из `GITHUB_SHA` (первые 7 символов), иначе из `git rev-parse --short HEAD`, иначе `unknown`. Типы объявляются в `vite-env.d.ts`, значения читает только `src/app`.

8. **Действия меню — список.** `SettingsEntryContext` хранит `SettingsEntry[]`. Вложенный провайдер добавляет свои пункты к унаследованным. `BackupProvider` (`src/app/backup/`) оборачивает `InstallProvider`, отсюда порядок «выгрузить, восстановить, установка». Пункты резервной копии отдаются только на каталоге, доске и карточке; в `loading`, `unavailable` и при `restartRequired` их нет.
   - Альтернатива — отдельные пропсы шапки для каждого действия. Она размножает пропсы через все экраны фичи.

9. **Порядок шагов восстановления** сохраняет пользовательскую активацию для выбора файла:
   ```
   пункт меню --(синхронно в обработчике клика)--> input[type=file].click()
     -> cancel: ничего | change: file.text() -> parseBackup
       -> invalid/newer: диалог ошибки
       -> ok: диалог сравнения
            [Сначала выгрузить] -> обычная выгрузка, диалог открыт
            [Отмена] -> закрыть, фокус на шестерёнку
            [Заменить] -> закрыть -> requestLeave(...)
                 -> store.restoreBackup -> navigate('') -> уведомление
   ```
   Защита черновиков срабатывает на «Заменить», а не до выбора файла. Если показать вопрос о черновиках до `input.click()`, браузер (особенно Safari) отклонит программное открытие выбора файла без свежей активации. Поведение соответствует спецификации: защита срабатывает до любых изменений. `accept=".json,application/json"`.

10. **Доставка файла.** `new File([json], name, { type: 'application/json' })`. Если `matchMedia('(pointer: coarse)')` и `navigator.canShare?.({ files: [file] })`, вызывается `navigator.share({ files: [file] })`. `AbortError` означает отмену и молча игнорируется. `NotAllowedError` (активация истекла, пока шло чтение IndexedDB) и прочие ошибки share переводят на скачивание. Скачивание идёт через `URL.createObjectURL` и временный `<a download>`, объект URL затем отзывается. Имя файла строится по локальному времени.
   - Условие «сенсорный ввод» уточняет подтверждённое «если доступно»: Safari и Chrome на macOS тоже поддерживают отправку файлов, но на компьютере ожидается скачивание.

11. **Диалоги.** Используется `ActionDialog` из фичи (фокус, Escape, блокировка фона). Ошибки выгрузки, разбора и записи показываются диалогом с текстом и кнопкой «Закрыть»: уведомления по спецификации `application-shell` ошибок не несут. Успех восстановления показывает обычное уведомление. Даты и числа форматирует `Intl` в языке интерфейса.

## Risks / Trade-offs

- [iOS PWA: `share` после асинхронного чтения теряет активацию] → откат на скачивание. Фактическое поведение подтверждается на реальном iPhone при приёмке выпуска.
- [iOS может не дать выбрать `.json` при `accept="application/json"`] → в `accept` указаны и расширение, и MIME-тип. Это тоже проверяется на устройстве.
- [Устаревшая вкладка после восстановления в другой] → вне рамок. Её записи в удалённые сущности отклоняются существующими проверками транзакций, перезагрузка показывает новые данные.
- [Строгая схема отклоняет файл, отредактированный вручную] → так задумано: копию создаёт только приложение.
- [Будущая миграция схемы без новой версии формата] → тест сравнивает версию Dexie с ожидаемой для текущей версии формата. Изменение схемы без решения о формате остановит проверку.

## Migration Plan

Схема IndexedDB не меняется, поэтому откат выпуска безопасен. В том же PR нужно:
- дополнить `docs/release-checklist.md` пунктом проверки выгрузки и восстановления на реальных устройствах, включая установленный PWA на iPhone;
- в `README.md` заменить фразу о будущем backup/export и упомянуть перенос данных из Safari в установленное приложение через копию.
