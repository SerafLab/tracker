# Видение продукта

Статус: первичная версия по итогам product discovery 6 октября 2026 года, дополненная требованиями к устройствам и браузерам в техническом интервью. Описывает намерения и границы продукта; реализация ещё не подтверждена.

## Цель проекта

Создать персональный трекер домашних проектов и пройти полный цикл разработки с AI-инструментами и подходом SDD на примере OpenSpec: от понимания проблемы до опубликованного приложения.

Главный критерий успеха автора — освоение воспроизводимого процесса разработки и понимание его трудоёмкости. Полезность приложения проверяется на собственных реальных делах. Даже если продукт окажется неудачным, полученный опыт должен позволить осознанно сделать следующий.

Первый цикл заканчивается публикацией работающей веб-версии. Дальнейшая учебная цель — создать приложения для Android и iOS и опубликовать их в магазинах. Срок и бюджет времени пока не определены.

## Проблема

У пользователя одновременно идут длительные дела: поиск квартиры, получение паспорта, оформление наследства, продажа недвижимости. Внутри одного дела могут параллельно продвигаться несколько объектов или направлений работы.

Сведения распределены между текстовыми файлами, перепиской и памятью. Пользователь теряет договорённости и забывает очередные действия. Возвращаясь к делу, ему приходится восстанавливать контекст: на каком этапе оно находится, чего он ждёт и что нужно сделать дальше.

Два основных вопроса пользователя:

- На каком этапе находятся начатые дела и что зависло?
- Где найти сведения, необходимые для продолжения конкретного дела?

Пока проблема подтверждена личным опытом автора. Потребность широкой аудитории не исследована.

## Пользователь и первый сценарий

Пользователь первой версии — сам автор, который ведёт свои дела самостоятельно.

Проверочный сценарий MVP — поиск квартиры. Пользователь находит несколько объектов, сохраняет ссылки и сведения, общается с агентами, договаривается о просмотрах и выбирает подходящий вариант. Каждый объект находится на своём этапе и требует своего следующего действия.

История совместного поиска квартиры помогла обнаружить проблему сохранения контекста. Совместная работа с женой или другими участниками не является условием первой версии.

Получение паспорта, оформление наследства и продажа недвижимости — будущие сценарии проверки общей модели. Их полноценная поддержка пока не доказана.

## Продуктовое обещание

Открыв проект, пользователь может увидеть положение каждой карточки, её следующее действие и сохранённые договорённости, чтобы продолжить работу без восстановления контекста по памяти и разрозненной переписке.

В MVP «увидеть, что зависло» означает просмотреть статусы, следующие действия и визуально выделенные прошедшие даты. Ожидание другого человека обозначается вручную. Автоматического определения длительного бездействия или непонятного следующего шага пока нет.

## Общий словарь

| Термин | Значение | Пример |
| --- | --- | --- |
| Проект | Отдельное большое дело, объединяющее карточки и собственные статусы | «Поиск квартиры» |
| Доска | Представление проекта по колонкам статусов | Все рассматриваемые квартиры, распределённые по этапам |
| Карточка | Единица внутри проекта, которая движется по этапам и хранит свой контекст | Конкретная квартира |
| Статус | Текущий этап карточки; на доске представлен колонкой | «Договорились о просмотре» |
| Следующее действие | Одно актуальное действие по карточке | «Уточнить размер депозита» |
| Дата действия | Необязательная дата, при необходимости со временем, относящаяся к следующему действию | Просмотр 15 октября в 17:00 |
| Заметка | Отдельная текстовая запись с датой, сохраняющая сведения или договорённости | «Агент подтвердил размер депозита» |
| История заметок | Последовательность записей, позволяющая вернуться к прежним договорённостям | Результаты нескольких звонков и встреч |
| Резервная копия | Файл с данными приложения для ручного сохранения и последующего восстановления | Сохранённая копия проектов, карточек и заметок |

«Этап» используется как обычный синоним статуса. Для следующего действия в MVP нет отдельной сущности с собственным списком подзадач. Значение карточки за пределами поиска квартиры ещё предстоит проверить.

## Согласованный MVP

Пользователь может:

1. Вести несколько независимых личных проектов.
2. Создавать и переименовывать статусы в каждом проекте.
3. Создавать карточки и перемещать их между статусами.
4. Сохранять в карточке текст и ссылки. Цена, район и подобные сведения записываются обычным текстом.
5. Добавлять отдельные заметки с датами, сохраняя историю договорённостей.
6. Указывать одно актуальное следующее действие и необязательную дату и время.
7. Видеть на доске статус, следующее действие и его дату. Прошедшая дата визуально выделяется при открытии приложения.
8. После первого открытия опубликованного приложения с интернетом повторно открывать его и работать с локальными данными без интернета.
9. Вручную выгружать все данные в резервную копию и восстанавливать их из неё.

Пример статусов проверочного проекта: «Найдено», «Написали», «Договорились о просмотре», «Посмотрели», «Рассматриваем», «Отказались», «Выбрали». Это пример настройки проекта, а не обязательная схема для всех пользователей.

Первая версия хранит данные локально в браузере. Предполагаемое хранилище из исходного замысла — IndexedDB; техническое обоснование и остальной стек относятся к следующему этапу работы. Автоматического переноса данных между устройствами нет.

Веб-MVP должен быть пригоден для использования с телефона. Chrome входит в обязательную поддержку; остальные браузеры пока обсуждаются. Основной телефон автора — iPhone; Android-телефон также доступен для проверки. Поддерживаемые версии ещё не определены. Это требование к веб-версии; выпуск отдельных приложений Android и iOS остаётся следующим этапом. Автор подтвердил приемлемость независимых локальных данных устройств без синхронизации и авторизации пользователя в MVP.

Сохраняется сама ссылка; доступность внешней страницы без интернета не обещается. Резервное копирование выполняет пользователь: автоматической облачной копии в MVP нет.

## Условия завершения первого цикла

Первый цикл завершён, когда опубликованная веб-версия позволяет пройти реальный сценарий поиска квартиры:

- Сохранить несколько объектов и распределить их по разным статусам.
- Записать результаты звонков или встреч и позже найти прежние договорённости.
- Указать разные следующие действия по объектам, включая действие с датой и временем.
- При открытии доски увидеть следующие действия и прошедшую дату.
- После первоначальной загрузки повторно открыть приложение без интернета, продолжить работу и сохранить изменения между открытиями.
- Выгрузить резервную копию и восстановить из неё проекты, статусы, карточки, текст, ссылки, заметки и даты.
- Пройти основной сценарий с телефона и в Chrome на согласованных платформах, включая повторное открытие без интернета и работу с резервной копией.

Это критерии готовности первой версии. Гипотезу о том, что приложение уменьшает забывание действий и потерю контекста, нужно дополнительно проверить личным использованием.

## Принципы разработки и документации

- GitHub — основной репозиторий и история проекта.
- Разработка идёт небольшими изменениями с проверяемым результатом.
- Спецификации хранятся в репозитории; OpenSpec выбран для изучения SDD и ведения поведения продукта.
- `openspec/specs/` описывает текущее реализованное поведение; планы не должны выдаваться за уже работающие возможности.
- `openspec/changes/` содержит предложения и изменения в работе.
- `docs/adr/` предназначен для значимых и труднообратимых технических решений.
- Эти продуктовые документы фиксируют проблему, направление, границы и гипотезы. Они не заменяют спецификации поведения.

Следующие этапы описаны в [roadmap.md](roadmap.md), ограничения — в [non-goals.md](non-goals.md), непроверенные предположения — в [assumptions.md](assumptions.md).
