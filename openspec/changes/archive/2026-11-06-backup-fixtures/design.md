# Design

## Context

Индекс заметок `[cardId+createdAt]` сравнивает строки. `isIsoDate` принимает любое смещение. Генератор тестовых копий добавлен в `scripts/backup-fixtures.mjs` без типов, пока формат был в работе.

## Goals / Non-Goals

**Goals:** формат дат копии совпадает с тем, что пишет приложение; набор копий проверяется типами и тестами.

**Non-Goals:** сортировка заметок по разобранной дате; нормализация дат при восстановлении (копия ничего не исправляет); тест скорости на нагрузочной копии.

## Decisions

1. **Дата корректна, если `new Date(value).toISOString() === value`.** Одна проверка отсекает смещения, отсутствие миллисекунд, `24:00` и несуществующие дни, потому что любое из них меняет строку при обратном преобразовании. Регулярные выражения `ISO_DATE` и `DATE_PARTS` удаляются.
   - Альтернатива — сортировка заметок по `Date.parse`: чинит одно место, а строковое сравнение дат остаётся во всех прочих.
2. **Генератор — `src/test/backup-fixtures.ts`** с типом `Backup` из `features/project-board`. `tsc` ловит расхождение с форматом; Node 24 запускает файл напрямую, потому что импорт только типовой. Файлы для ручной проверки пишет `npm run fixtures:backup` в игнорируемый `fixtures/backup/`.
3. **E2e получает копию из генератора в памяти** и передаёт её в выбор файла буфером. Проверки: у страницы нет горизонтальной прокрутки, карточки, плитки и заметки не шире своих контейнеров, заголовок шапки в одну строку. Снимки сохраняются только для выборочного просмотра.

## Risks / Trade-offs

- [Копии, отредактированные вручную, с датами без миллисекунд отклоняются] → так задумано: копию создаёт только приложение.
