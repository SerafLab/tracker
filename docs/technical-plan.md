# Технический план веб-MVP

Статус: черновик по техническому интервью 6 октября 2026 года. Ниже разделены согласованные требования и предлагаемые решения. Реализация, настройка публикации и окончательное согласование стека ещё не выполнены.

## Исходные требования

- Автор имеет почти десять лет опыта с React и TypeScript. Учебная цель проекта — пройти полный цикл разработки с AI и OpenSpec.
- Первый выпуск — личное веб-приложение с локальными данными, повторным открытием без интернета и ручной резервной копией. Полные границы описаны в [vision.md](product/vision.md).
- Использование с телефона обязательно. Chrome входит в обязательную поддержку; остальные браузеры обсуждаются. Основной телефон автора — iPhone; Android-телефон также доступен для проверки. Точные версии ОС и браузеров ещё не зафиксированы.
- Автор предпочитает разместить первый MVP на GitHub.
- Аккаунты, автоматическая синхронизация и совместная работа относятся к последующим этапам.

## Предлагаемая основа

React и TypeScript предлагаются как привычная автору основа интерфейса, Vite — как средство локальной разработки и статической сборки. Конкретные версии и дополнительные библиотеки выбираются после согласования платформ и поведения; они пока не зафиксированы.

Для публикации предлагается GitHub Pages, для автоматической сборки, проверок и публикации — GitHub Actions. Pages раздаёт статические файлы, поэтому эта схема подходит текущему объёму с выполнением логики и хранением пользовательских данных в браузере. Серверная часть для этого предложения не требуется; при добавлении аккаунтов и синхронизации схема будет пересмотрена.

GitHub Pages предоставляет HTTPS. Для стандартного адреса проектного сайта вида `https://<owner>.github.io/<repo>/` нужно согласовать базовый путь приложения и учитывать его в сборке, ресурсах и области действия service worker. Официальная инструкция Vite описывает настройку `base` и публикацию каталога `dist` через Actions.

Это обоснованное предложение, а не уже настроенный деплой.

## Данные и работа без интернета

IndexedDB остаётся кандидатом для хранения проектов, статусов, карточек и заметок из исходного замысла. Обёртка над хранилищем, структура данных и правила миграций ещё не выбраны.

Для повторного открытия без интернета предлагается кеширование файлов приложения с помощью service worker. Хранение пользовательских данных и кеширование файлов приложения — разные задачи; сама публикация на Pages не обеспечивает офлайн-режим.

В текущих границах данные отдельны для каждого браузера и устройства. Публикация одного адреса на Pages не синхронизирует их: карточка, добавленная на компьютере, автоматически на телефоне не появится. Автор подтвердил, что для MVP это приемлемо: синхронизация и авторизация пользователя не входят в первый выпуск. Ручная резервная копия предусмотрена, но правила восстановления при наличии данных ещё не согласованы.

До использования реальных данных необходимо определить миграции, поведение при обновлении приложения и ограничения отката. Возврат старой сборки сам по себе не отменяет миграции пользовательских данных. Адрес публикации также следует выбрать осознанно: перенос на другой origin потребует отдельного плана переноса локальных данных.

## Предлагаемый путь от изменения до выпуска

1. Локально запустить приложение и проверить изменение по его спецификации OpenSpec.
2. В pull request выполнить согласованные автоматические проверки, включая проверку типов, тесты и production-сборку. Инструменты и состав тестов ещё выбираются.
3. После включения изменения в основную ветку собрать и опубликовать приложение через GitHub Actions в GitHub Pages.
4. Проверить опубликованную версию на согласованных устройствах: основной сценарий, повторное открытие без сети, сохранность данных и резервную копию.

На этапе подготовки реализации определить команды установки, запуска, проверки и сборки, пакетный менеджер, версию Node.js, механизм обновления кеша и порядок отката. Отдельное окружение для предварительных версий пока не согласовано.

## Открытые решения и проверки

- Зафиксировать версии ОС и Chrome для проверок на основном iPhone и доступном Android-телефоне. Отдельно проверить офлайн-открытие, сохранность данных и резервную копию на каждом устройстве; необходимость поддержки других браузеров остаётся открытой.
- Согласовать React, TypeScript, Vite и GitHub Pages как техническую основу.
- Проверить доступность Pages для фактической видимости репозитория и тарифа GitHub. По документации, на GitHub Free Pages доступны для публичных репозиториев; приватные репозитории поддерживаются на указанных платных планах. Определить публичность сайта до публикации.
- Выбрать хранение данных, маршрутизацию, механизм офлайн-работы и обновлений, средства проверки и поддержки интерфейса.
- Зафиксировать адрес публикации, команды разработки, процесс выпуска и отката.
- После согласования технического плана определить первое небольшое изменение в OpenSpec. Существенные труднообратимые решения с реальными альтернативами при необходимости вынести в ADR.
