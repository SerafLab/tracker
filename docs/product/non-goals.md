# Границы продукта

Статус: границы первого MVP, согласованные 6 октября 2026 года. Последующие направления перечислены в [roadmap.md](roadmap.md).

## Что не входит в веб-MVP

| Возможность | Граница первой версии |
| --- | --- |
| Аккаунты и авторизация | Личное использование с локальными данными браузера |
| Облачное хранение и автоматическая синхронизация | Ручная резервная копия и восстановление; доступ с разных устройств отложен |
| Участники и совместные обсуждения | Проекты ведёт один пользователь; заметки сохраняют его сведения и договорённости |
| Приложения Android и iOS, публикация в магазинах | Следующий этап после опубликованной веб-версии |
| Уведомления при закрытом приложении | Дата и её просроченность видны при открытии приложения |
| Автоматический поиск «зависших» карточек | Пользователь оценивает статусы и действия; ожидание обозначает вручную |
| Списки действий и подзадач внутри карточки | Одно актуальное следующее действие |
| Вложения и хранение файлов документов | Текст и ссылки; файл резервной копии нужен для выгрузки и восстановления данных приложения |
| Специальные поля недвижимости и операции с ними | Цена, район и подобные сведения записываются текстом; сортировка, фильтрация и сравнение по этим полям не входят в MVP |
| AI-помощник и интеграции с AI-окружениями | Дальнее направление, требующее отдельного исследования |

## Чего первая версия не обещает

- Приложение не гарантирует, что пользователь перестанет забывать действия. В MVP он должен сам открывать доску; внешних напоминаний нет.
- Локальное хранение не заменяет резервную копию. Пользователь вручную сохраняет её для восстановления после потери локальных данных.
- Сохранённая ссылка не означает, что содержимое внешнего сайта доступно без интернета.
- Статус карточки не определяет следующее действие автоматически.
- Универсальность для получения паспорта, оформления наследства, продажи недвижимости, ремонта, переезда и других дел пока не подтверждена.

## Что сознательно не определяем на этапе discovery

На завершённом этапе discovery не выбирались стек, способ реализации мобильных приложений, архитектура синхронизации или механизм AI-интеграции. Стек веб-MVP определяется отдельным техническим планом; остальные решения принимаются на соответствующих этапах с учётом уже проверенных потребностей.

Наличие будущей идеи в roadmap не означает, что ради неё уже нужно усложнять первую версию.

## Как расширять границы

Основание для расширения — наблюдаемая потребность в реальном сценарии или явно выбранная учебная цель следующего этапа. Изменение объёма описывается отдельно, получает проверяемое ожидаемое поведение и отражается в продуктовой документации. До реализации оно не считается текущей возможностью продукта.
