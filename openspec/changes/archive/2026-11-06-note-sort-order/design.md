# Design

## Context

- Репозиторий возвращает заметки карточки и последние пять заметок для доски уже отсортированными от старых к новым (`dexie-project-board-repository.ts`, сортировка по `createdAt`, затем `id`).
- `CardDetailView` выводит `details.notes` как есть; `CardView` показывает `notes.slice(-1)` в свёрнутом виде и весь массив в раскрытом.
- Предпочтения интерфейса уже хранятся в `localStorage` через контекст: тема (`src/ui/theme-provider.tsx`) и язык. Провайдеры подключены в `src/app/app.tsx`.
- На широком экране панель карточки и доска видны одновременно, поэтому выбор должен сразу доходить до обеих.

## Goals / Non-Goals

**Goals:**
- Одно общее предпочтение порядка, сохраняемое между перезагрузками, с немедленным обновлением панели и доски.

**Non-Goals:**
- Синхронизация выбора между открытыми вкладками (подхватывается при следующей загрузке).
- Переключатель на карточке доски.
- Изменение порядка в хранилище, в доменной модели и в ответах WebMCP.
- Сортировка по дате изменения.

## Decisions

1. **Порядок — забота представления.** Репозиторий и домен продолжают отдавать заметки от старых к новым; интерфейс разворачивает массив при «сначала новые». Альтернатива — сортировать в репозитории по параметру — протянула бы UI-настройку через use cases и агентский контракт без пользы.

2. **`NoteOrderProvider` по образцу темы.** Контекст `{ order: 'newest' | 'oldest'; toggle() }` в `src/features/project-board/presentation/note-order.tsx`, ключ `localStorage` в общем стиле ключей приложения. Начальное значение читается в `useState` инициализаторе в `try/catch`; всё, кроме `'oldest'`, даёт `'newest'`. Запись в `try/catch` без предупреждения: порядок не критичен, в отличие от темы. Провайдер оборачивает `ProjectBoardApp`: доска и подробности рендерятся внутри него, а приложение не импортирует внутренние модули фичи (граница архитектуры). Без провайдера (изолированные тесты компонентов) хук возвращает `'newest'`; тесты переключения оборачивают компонент в провайдер.
   - Альтернатива — состояние в zustand-сторе доски: смешивает настройку вида с данными доски; контекст проще и уже принят для предпочтений.
   - Альтернатива — `useSyncExternalStore` над `localStorage` со `storage`-событием: нужна только для синхронизации вкладок, которая вне цели.

3. **Помощник `orderNotes(notes, order)`** возвращает показанный массив (копия + `reverse()` для `'newest'`). Используется в истории и в раскрытом списке доски. Свёрнутая карточка продолжает брать самую новую заметку (`notes.at(-1)`) независимо от порядка.

4. **Переключатель.** Кнопка `button button-quiet button-icon` в заголовке истории (`h2` и кнопка в одной строке flex), две иконки в `BoardIcon`: `sortNewest` / `sortOldest` (стрелка с убывающими/возрастающими линиями в стиле текущих 24×24 stroke-иконок). Доступное имя — текущий порядок («Порядок заметок: сначала новые» / «Note order: newest first»), без `aria-pressed`, так как два состояния не являются «вкл/выкл». Кнопка не блокируется во время сохранения, так как не меняет данные.

5. **Место добавления.** Блок «кнопка добавления или редактор новой заметки» и блок списка — элементы массива с ключами `add` и `notes`; при `'newest'` и непустой истории массив `[add, notes]`, иначе `[notes, add]`. Благодаря ключам React переносит DOM-узел редактора, а не перемонтирует его: текст и `autoFocus` сохраняются без повторного захвата фокуса.

6. **Фокус после удаления** вычисляется по показанному массиву (`orderNotes(details.notes, order)`), а не по `details.notes`.

## Risks / Trade-offs

- [Существующие тесты и e2e проверяют порядок «от старых к новым»] → обновить ожидания на новый порядок по умолчанию и добавить проверки переключения; явно задавать порядок в тестах, где он важен.
- [Состояние `localStorage` протекает между e2e-тестами одного контекста] → Playwright создаёт новый контекст на тест; в unit-тестах очищать ключ в `afterEach`.
- [При переключении блок добавления меняет место в DOM; перемонтирование редактора с `autoFocus` увело бы фокус с переключателя] → блоки рендерятся с ключами, поэтому редактор переносится без перемонтирования; тест проверяет фокус на переключателе и сохранность черновика.
