# Ревью

Ревьюер получает этот файл, diff ветки с `origin/main`, изменение OpenSpec и [AGENTS.md](AGENTS.md). Цель — найти то, что сломает приложение или данные пользователя, а не улучшить стиль.

## Что считается поломкой

- Потеря или порча данных: миграция IndexedDB без перехода со старой версии, изменение формата бэкапа без чтения старых файлов, восстановление, которое стирает данные до проверки файла.
- Поведение расходится со сценариями спецификации или с заявленной целью PR. В исправлении бага устранена не первопричина.
- Нарушены границы слоёв из `scripts/check-architecture.mjs` или их обходят.
- Тест удалён, ослаблен или проверяет реализацию, а не сценарий спецификации; новое поведение без теста; тест нарушает [правила тестов](docs/agents/rules/testing.md).
- Текст интерфейса без ключей i18n для обоих языков.
- Обновление service worker оставляет установленную копию на старой версии.

## Не сообщать

- Мелкие замечания по стилю, именам и форматированию.
- Проблемы, которых этот diff не вносит, — только с пометкой «Pre-existing», если они серьёзные.

## Формат

- Сводка начинается с числа находок. Если исправлять нечего, так и написать.
- Каждая находка: важность (Important / Nit / Pre-existing), `файл:строка`, доказательство и сценарий сбоя. Без доказательства находку не публиковать.
- Если находка — класс ошибок, перечислить все её экземпляры в diff.

## Рискованные пути

Список — `HIGH_RISK_PATHS` в [scripts/risk-paths.mjs](scripts/risk-paths.mjs): данные пользователя, service worker, зависимости, CI и хуки, правила агентов. PR, который их затрагивает, сливается только после проверки человеком: человек ставит метку `human-approved`. Агент метку не ставит. Workflow `Human approval` (проверка `high-risk-paths`) судит PR по списку из `main` и снимает метку при новом push; хук Claude Code разрешает слияние только после успешной проверки на текущих коммитах.
