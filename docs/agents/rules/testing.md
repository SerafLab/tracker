# Тесты

## Асинхронность

CI медленнее локальной машины, поэтому тест, который полагается на тайминг, проходит локально и падает в CI. При написании и изменении тестов:

- После действия, запускающего асинхронную работу (сохранение, загрузку, открытие или закрытие диалога, перенос фокуса), ждать результата: `findBy*`, `waitFor`, в Playwright — `expect(locator)` с автоожиданием. Синхронные `getBy*`, `toHaveFocus()`, `toHaveValue()` и чтения из репозитория допустимы только после такого ожидания.
- Ждать конкретный наблюдаемый результат последнего шага, а не промежуточный признак. Исчезновение диалога не гарантирует возврат фокуса; появление текста не гарантирует запись в хранилище.
- Не использовать фиксированные задержки (`setTimeout`, `waitForTimeout`) и не увеличивать таймауты вместо ожидания условия.
- Новые и изменённые тестовые файлы перед отправкой прогонять повторно: `npx vitest --run --repeats=10 <файлы>`, для e2e — `npx playwright test <файлы> --repeat-each=5`.
- Если тест упал в CI, но проходит локально, искать и исправлять в нём все несинхронизированные проверки, а не только упавшую строку.
- Перед следующим последовательным шагом навигации ждать завершённый переход: адрес внутри страницы (`page.evaluate(() => location.href)`), закрытую панель и отрисованный целевой экран. `page.url()` может отставать от same-document переходов истории. Намеренно быстрые действия (двойной Back) не сериализовать: это проверяемый сценарий.
- Нестабильный тест не удалять и не ослаблять. Сначала установить, гонка ли это приложения или несинхронизированный тест; без доказанной причины сохранить регрессию и записать ограничение в [test-reliability.md](../test-reliability.md).
- Подписку на событие, которым завершается шаг (`scroll`, `scrollend`), устанавливать на целевом элементе и дожидаться её установки до отправки события. Глобальные слушатели ловят чужие события, например `scrollend` предыдущей программной прокрутки.
- Результат жеста измерять как изменение позиции целевого элемента от измеренного начального значения в нужном направлении, а не как абсолютный порог: начальная позиция может быть ненулевой, а scroll snapping возвращает конечную позицию назад. Ослабление порога или увеличение таймаута само по себе не исправление.

## Изоляция и диагностика browser-прогонов

- Playwright не переиспользует чужой сервер: занятый порт — явная ошибка. Каждый checkout запускает проверки на своём порту: `E2E_PORT=<свободный порт> npm run check` (и `git push`, который запускает хук). Порт 4173 по умолчанию делят все сессии.
- Не запускать одновременно build или check в одном checkout: `dist/`, `test-results/` и `playwright-report/` общие для него.
- Retries выключены. Trace первого сбоя (включая контексты из `browser.newContext()`) сохраняется в `test-results/`, отчёт — в `playwright-report/` (`npx playwright show-report`). В CI те же каталоги выгружаются артефактом `browser-diagnostics-<run>-<attempt>` при сбое. Разбор начинать с trace первого сбоя; успешный перезапуск не доказывает исправление.
- Стресс для воспроизведения — ограниченный и записанный: CDP `Emulation.setCPUThrottlingRate`, число повторов и workers, `--retries=0`. Временные probes удалять после диагностики.

## Скриншоты

При ошибке сборки или обычного теста сначала читать текст ошибки и относящийся к нему код. Скриншоты после прогона не открывать; визуальная проверка описана в [visual-review.md](visual-review.md).
