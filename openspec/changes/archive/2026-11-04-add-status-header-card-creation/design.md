# Design

## Context

Мотивация и границы поведения описаны в `proposal.md` и `specs/project-boards/spec.md`. Сейчас `StatusColumn` содержит одну нижнюю кнопку, `creatingCard` и `createTrigger`, передаваемый в `CardDialog.returnFocus`. `ActionDialog` уже возвращает фокус с `preventScroll: true`.

Верхняя кнопка добавления статуса использует `.button-primary.button-icon` (44×44 px) и локализованную подсказку `.bar-hint`. `BoardIcon` содержит тот же SVG плюса. Заголовок колонки построен на flex, название допускает переносы, а `.add-card` сейчас задаёт широкую тихую кнопку и уменьшает символ плюса. Браузерные тесты проверяют нижнее расположение через `.add-card`; многие тесты ожидают единственный доступный `Add card` внутри статуса.

Документ нужен для решения двух деталей до реализации: выбор конкретного инициатора при возврате фокуса и единая область нажатия нижнего плюса с подписью.

## Goals / Non-Goals

**Goals:** переиспользовать одну форму и обработчик создания, сохранить корректный фокус для двух входов, использовать общий визуальный язык плюса без копирования цветовых значений; ограничить высоту рабочей области доски доступной высотой окна и прокручивать карточки внутри колонок.

**Non-Goals:** закрепление заголовка колонки при прокрутке списка, изменение порядка новых карточек, новый сценарий редактирования, универсальная переработка системы кнопок или изменение высоты каталога проектов.

## Decisions

### Два инициатора, одна форма

Оставить локальное состояние открытия формы в `StatusColumn`. Обоим входам назначить отдельные refs и при открытии сохранять выбранный источник; в `CardDialog.returnFocus` передавать ref именно этого источника. Не дублировать диалог и не полагаться на активный элемент после открытия: активный элемент уже принадлежит форме, а текущий фиксированный ref всегда возвращал бы пользователя вниз. Существующий механизм `ActionDialog` с `preventScroll` сохраняется.

### Общий вид плюса, разная подпись

Верхний вход — семантический button с существующими классами зелёной кнопки-иконки и `BoardIcon name="plus"`. Он расположен после группы названия и счётчика, перед `ActionMenu`.

Нижний вход остаётся одним семантическим button после `card-list`; внутри зелёная квадратная область плюса 44×44 px и видимый текст рядом. Область плюса использует общие размеры, цвет, радиус и SVG с верхней кнопкой и добавлением статуса; состояния наведения, нажатия и фокуса действуют на весь button. Для оформления переиспользовать общие правила и токены, при необходимости выделив небольшой общий стилевой класс. Не создавать вложенный button или вторую остановку Tab. Вариант целиком зелёной широкой плашки отклонён: пользователь согласовал одинаковый квадратный плюс с подписью рядом.

Сохранить `.add-card` для нижнего входа и убрать конфликтующие локальные правила уменьшения SVG. Верхний вход получает отдельный понятный признак для точного выбора в тестах. Производственный код не сохраняет совместимость со старыми предположениями тестов о единственной кнопке.

### Локализация, подсказки и длинные названия

Использовать существующий ключ `addCard` для текста, доступного имени верхней кнопки и подсказки. Подсказка показывается при наведении и фокусе и остаётся читаемой в прокручиваемой доске. Сначала переиспользовать существующий стиль подсказки; если проверка браузера обнаружит обрезание границами `.status-columns`, разместить подсказку в верхнем слое существующим механизмом popover. Новая библиотека не нужна.

Сохранить `min-width: 0` и перенос названия, запретить сжатие обеих кнопок заголовка и счётчика. Колонка может стать выше из-за переноса названия; сохраняются существующие минимальные ширины и правила горизонтальной прокрутки. Заголовок не становится закреплённым, оба входа видимы независимо от наведения мыши.

### Доска ограничена окном, прокручиваются карточки

Ограничение рабочей области доски высотой доступного viewport под закреплённой верхней панелью уже реализовано в `add-card-details` (решение пользователя 2026-11-04, `.board-workspace` с динамической высотой viewport); это изменение использует его и не вводит второй механизм. `.status-columns` растягивается на оставшуюся высоту и не увеличивается из-за содержимого. Колонки сохраняют общую сетку subgrid из `board-column-visual-separation` с рядами заголовка, списка и нижнего действия: ряд списка получает `minmax(0, 1fr)`, вертикальную прокрутку получает только `.card-list`, а кнопка добавления остаётся отдельным нижним элементом колонки. Колонки не переводятся на flex, чтобы не потерять выравнивание начала списков. Горизонтальная прокрутка статусов сохраняется. Высота каталога и других экранов не меняется.

Верхний плюс создания карточки показывать во всех статусах всегда; нижние входы показывать во всех статусах только когда суммарное число карточек доски больше нуля. При нуле карточек скрыть только нижние входы во всех колонках; верхние плюсы создания карточки остаются во всех статусах (решение пользователя), глобальный плюс добавления статуса в верхней панели также остаётся. Состояние вычисляется из уже загруженной доски, отдельное хранение не требуется. После создания первой карточки нижние входы появляются, после удаления последней — скрываются; верхние плюсы остаются доступными. Не переносить верхний плюс добавления статуса в колонки и не путать его с верхним входом добавления карточки.

### Проверки поведения вместо единственного совпадения

Адаптировать общие помощники в `src/app.test.tsx` и селекторы создания в UI/e2e к конкретному входу: заголовок либо нижняя `.add-card`. Не заменять их случайным первым совпадением. Существующую проверку `createAfterCards` сохранить для нижней кнопки. Добавить целевые сценарии обоих источников, возврата фокуса после сохранения/отмены/Escape и нижнего действия при прокрученной длинной доске.

## Risks / Trade-offs

- Дополнительная кнопка уменьшает ширину названия → проверить длинные статусы на 320/390/1280/1440 px, переносы и сохранение четырёх колонок на широком экране.
- Ограниченная высота может обрезать колонку, если ряды сетки и список не разрешают сжатие → на уровне доски, контейнера колонок и списка задать корректные ограничения минимальной высоты и проверить прокрутку в браузере при изменении viewport, включая мобильную панель браузера.
- Отдельная прокрутка карточек меняет привычную прокрутку всей страницы → проверить доступность нижнего действия, клавиатурный фокус и горизонтальное перемещение между колонками при длинных списках.
- Условие отображения зависит от всех колонок → проверять пустую доску, первую карточку в любой колонке и удаление последней карточки, чтобы входы переключались согласованно.
- Одинаковое доступное имя двух входов делает прежние селекторы неоднозначными → выбирать кнопки по их месту внутри конкретного статуса, сохраняя общее понятное имя для пользователя.
- Нижняя кнопка может сместиться после добавления карточки → возвращать фокус с `preventScroll`; проверять отсутствие прыжка к заголовку, не требовать побитового сохранения координат после изменения содержимого.
- Подсказка в scroll-контейнере может обрезаться → проверить её границы в первой и последней колонках с горизонтальной прокруткой и при необходимости использовать верхний слой.
- `add-card-details` может менять тот же файл представления и тесты → при совместной реализации сохранить его форму создания и объединить изменения явно; зависимости по модели данных нет.

## Migration Plan

Миграция данных и изменение API отсутствуют. При реализации выполнить `npm run check`, перенести дельта-спецификацию в основную и архивировать изменение в той же ветке перед готовым PR согласно правилам проекта. Возврат предыдущего интерфейса возможен обычным откатом изменения без преобразования пользовательских данных.
