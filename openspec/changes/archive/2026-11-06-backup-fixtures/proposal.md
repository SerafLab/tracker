# Proposal

## Why

Восстановление принимает даты ISO 8601 с любым смещением (`+03:00`), а заметки хранилище упорядочивает сравнением строк дат. Копия со смещениями восстанавливается с неверным порядком заметок, хотя приложение само пишет только UTC. Кроме того, интерфейс после восстановления не проверялся на длинных текстах, большом числе колонок и заметок.

## What Changes

- **BREAKING (формат копии v1)**: даты копии принимаются только в UTC в виде, который пишет приложение (`2026-11-06T12:00:00.000Z`); смещения, даты без миллисекунд и несуществующие даты делают копию повреждённой. Формат ещё не публиковался вне разработки.
- Генератор тестовых копий `npm run fixtures:backup`: крайние случаи, нагрузка и отклоняемые файлы для ручной проверки восстановления; файлы не хранятся в репозитории.
- Unit-тест: каждая сгенерированная копия даёт ожидаемый результат разбора.
- E2e: восстановленная копия крайних случаев не создаёт горизонтального переполнения в каталоге, на двух досках и на странице карточки при 320 и 1280 px.
