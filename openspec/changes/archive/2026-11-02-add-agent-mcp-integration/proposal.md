# Proposal

## Why

Пользователь хочет добавлять и просматривать задачи из разговора с агентом, а по просьбе «покажи задачи» видеть EasyTrack во внутреннем браузере. Данные должны оставаться в существующем браузерном хранилище без автоматизации форм и серверной базы.

Проверка опубликованного HTTPS EasyTrack не подтвердила loopback WebSocket. После отдельного native WebMCP эксперимента на production пользователь 2026-11-02 явно выбрал «Да, реализовать WebMCP» вместо Node/stdio-сервера. История отказа и успешный marker-only эксперимент сохранены в `docs/agents/mcp-browser-qa.md`; они не означают готовность инструментов работы с задачами.

## What Changes

- Предоставить native page tools просмотра проектов/досок, создания и переименования проектов/статусов, изменения порядка статусов, создания, изменения названия/признаков, переноса и удаления карточек и удаления пустых статусов.
- Регистрировать инструменты в документе EasyTrack через native WebMCP и исполнять команды только в явно выбранной вкладке и её сессии через операции приложения. Отдельного Node-процесса, stdio endpoint, relay, pairing или постоянного доступа нет.
- Поддерживать только host со средствами native WebMCP discovery/execution и управления внутренними вкладками. Обычное локальное и офлайн-приложение продолжает работать при отсутствии API/агента; универсальная совместимость со stdio MCP-клиентами не обещается.
- Возвращать подтверждённые сохранённые данные, обновлять текущий экран без неожиданной навигации и потери черновиков, различать отказ записи, ошибку обновления представления и неопределённый результат прерванного вызова. Повторный ID не исполняет мутацию заново; автоматического replay нет.
- Сохранить согласованный объём команд: `create_project` получает только имя и создаёт пустую доску, `create_card` начинает с пустого описания, `update_card` меняет только название/важность/срочность и транзакционно сохраняет актуальное описание. `move_card` добавляет в конец собственной группы через общий контракт размещения.
- Добавить агентный skill для выбора вкладки/сессии, разрешения ID, вызовов и показа приложения. `show_workspace` возвращает conflict при несохранённых черновиках; успех подтверждает фактически применённый маршрут.

## Capabilities

### New Capabilities

- `agent-task-access`: typed native WebMCP page tools, выбор документа/сессии, сохранённые результаты, отказоустойчивый workflow агента и показ рабочей доски.

### Modified Capabilities

Нет. Интеграция сохраняет существующие правила доски, локальности данных, черновиков и публикации.

## Impact

- Browser-native регистрация и command adapter в composition root, публичные контракты feature, use cases/repository, контекстное обновление Zustand и общий stale/pending guard; прямой доступ адаптера к Dexie исключён.
- Явная операция изменения атрибутов карточки с сохранением описания внутри той же транзакции, подтверждённые результаты мутаций и проверки отсутствующих/чужих целей. Схема IndexedDB не меняется.
- Browser-compatible схемы входов и результатов; Node MCP SDK/WebSocket транспорт в реализацию не добавляются. Опубликованные диагностические страницы остаются отдельно от task API и не заменяют его приёмку.
- Репозиторный skill, руководство поддерживаемых hosts, обновлённые продуктовые границы и ADR, unit/state/contract/browser tests с отдельно обозначенными fixtures, реальная native приёмка кандидата и production после выпуска.
- Вне объёма: аккаунты, облако, синхронизация, другая база/origin, произвольный eval, DOM CRUD, внешние браузеры, tool удаления проекта, note CRUD, редактирование описания через tool, пресеты через `create_project`, batch и гарантии exactly-once после reload. Автоматическое создание пользовательского чата и изменение глобальной конфигурации не входят в объём.
