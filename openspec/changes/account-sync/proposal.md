# Proposal

## Why

Проекты EasyTrack живут только в IndexedDB одного браузера: телефон и компьютер видят разные данные, а перенос возможен только через ручную копию. Пользователь решил сделать аккаунт и синхронизацию до выпуска в магазины, чтобы мобильные приложения сразу работали с общими данными. Провайдер выбран — Dexie Cloud: он синхронизирует существующую базу Dexie без своего сервера, а выход из него обеспечивает уже существующая выгрузка JSON.

## What Changes

- Аккаунт необязателен. Без входа приложение работает как сейчас, локально и офлайн. Вход включает синхронизацию проектов, статусов, карточек и заметок между устройствами.
- Способы входа: одноразовый код на e-mail и Google. Интерфейс входа свой (RU/EN, обе темы), а не стандартный диалог Dexie Cloud. Архитектура допускает третий способ (Sign in with Apple) и оболочку Capacitor позже.
- Изменения офлайн сохраняются на устройстве и синхронизируются при появлении сети. Конфликты: последняя запись побеждает по каждому полю; заметки — отдельные записи, поэтому сохраняются все; удаление побеждает правку.
- Первый вход выгружает локальные данные в аккаунт. Если на устройстве есть проекты, до входа показывается диалог «На устройстве N проектов, они объединятся с проектами аккаунта» с «Выгрузить копию» (диалог остаётся), «Объединить» и «Отмена». Объединение — это объединение множеств записей по уникальным ID.
- В начале страницы настроек появляется раздел «Аккаунт и синхронизация». Без входа: пояснение, «Войти через Google», поле e-mail и ввод кода. После входа: e-mail, состояние синхронизации («Синхронизировано», «Нет сети, изменения сохранены на устройстве», ошибка, «Нужно войти снова»), «Выйти», «Удалить аккаунт».
- Шестерёнка из `settings-page` становится значком аккаунта: без входа — контур человека, после входа — круг с первой буквой e-mail. Точка на значке появляется только когда нужно действие пользователя (повторный вход или ошибка синхронизации); отсутствие сети проблемой не считается. Фото профиля Google не используется.
- Выход удаляет данные с устройства (в облаке они остаются). Если есть несинхронизированные изменения, приложение предупреждает и предлагает сначала выгрузить копию.
- Удаление аккаунта (GDPR): подтверждение, удаление данных в облаке и на устройстве.
- Выгрузка копии доступна всегда. Восстановление при входе разрешено с явным предупреждением, что оно заменит данные на всех устройствах аккаунта.
- Настройки устройства (тема, язык, порядок заметок, последний проект, приглашение к установке) не синхронизируются; таблица `workspace` остаётся локальной.
- Инструменты агента (WebMCP) не меняются: они пишут локально, синхронизация разносит изменения.
- **ДОПУЩЕНИЕ, требует подтверждения:** на этом этапе синхронизацией пользуется только автор (и, возможно, тестировщики) в пределах трёх бесплатных мест Dexie Cloud. Вход ограничен списком разрешённых адресов; остальные видят понятное сообщение «Синхронизация доступна по приглашению». Возможность такого ограничения на стороне Dexie Cloud проверяется прототипом.
- Работа начинается с ограниченного по времени прототипа, который проверяет непроверенные свойства Dexie Cloud и даёт решение «продолжать / остановиться».
- Документы: `docs/product/roadmap.md` и `docs/product/non-goals.md` (синхронизация перед магазинами), новый ADR-0006, термины в `GLOSSARY.md`.
- Вне рамок: мобильные приложения (Capacitor), платежи и подписки, Sign in with Apple, свой домен, политика конфиденциальности, юридические и налоговые вопросы, совместная работа.

## Capabilities

### New Capabilities
- `account-sync`: необязательный аккаунт, вход по коду и через Google, синхронизация данных проектов, первый вход с объединением, правила конфликтов, состояние синхронизации, выход и удаление аккаунта.

### Modified Capabilities
- `app-settings`: раздел «Аккаунт и синхронизация» становится первым разделом страницы настроек.
- `application-shell`: шестерёнка становится значком аккаунта с буквой и точкой «нужно действие».
- `data-backup`: восстановление при входе предупреждает о замене данных на всех устройствах.
- `offline-installed-app`: подсказка о локальном хранении учитывает синхронизацию после входа.

## Impact

- Зависимость `dexie-cloud-addon`; база Dexie Cloud (облачный сервис, закрытый сервер), разрешённые origin, настройка Google OAuth в Dexie Cloud Manager.
- `src/features/project-board/infrastructure/indexeddb/`: подключение аддона, версия схемы 4, `workspace` в `unsyncedTables`, запись изменений полями (`update`), снятие служебных полей Dexie Cloud при чтении и копии.
- Порядок и целостность: чтение терпит повторы и пропуски позиций и «сирот» после слияния; выгрузка копии нормализует данные.
- Новая фича `src/features/account/`: порт облачного аккаунта, чистая модель состояния, адаптер Dexie Cloud и фальшивый адаптер для тестов.
- `src/app/settings/`, `src/ui/app-bar.tsx`, `src/app/backup/`, `src/i18n/resources.ts`.
- `scripts/check-architecture.mjs`: правила слоёв для второй фичи.
- Сборка: адрес базы через переменную окружения; тестовые сборки без реального облака.
- Документы: roadmap, non-goals, ADR-0006 (частично заменяет ADR-0001 и ADR-0002), GLOSSARY, README, `docs/release-checklist.md`.
- Зависит от изменения `settings-page`: оно должно быть реализовано и архивировано первым.
