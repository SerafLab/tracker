# Proposal

## Why

Пользователь хочет добавлять и просматривать задачи из разговора с агентом, а по просьбе «покажи задачи» видеть EasyTrack во внутреннем браузере. Для этого нужен программный интерфейс MCP с существующим браузерным хранилищем, без автоматизации форм и преждевременного перехода на серверную базу.

## What Changes

- Добавить MCP-инструменты просмотра проектов и досок, создания и переименования проектов и статусов, изменения порядка статусов, создания, изменения, переноса и удаления карточек и удаления пустых статусов.
- Передавать команды в открытый EasyTrack через аутентифицированный мост; выполнять существующие операции приложения и сохранять данные только в IndexedDB выбранного браузерного контекста.
- Обновлять отображаемую доску после программных изменений; возвращать успех только после сохранения, различать отказ операции и неопределённый результат при обрыве связи.
- Добавить агентный skill: подключать приложение, открывать его при необходимости в фоне и показывать выбранную доску во внутреннем браузере по запросу. MCP не должен запускать внешний браузер.
- Сохранить адрес GitHub Pages и самостоятельную офлайн-работу приложения. Локальный процесс MCP служит транспортом, не хранилищем задач.

## Capabilities

### New Capabilities

- `agent-task-access`: MCP-контракт операций с проектами, статусами и карточками, браузерное исполнение, подключение выбранной вкладки и показ приложения агентом.

### Modified Capabilities

Нет. Существующие правила доски, локальности данных и публикации сохраняются; новая возможность использует их и отдельно определяет агентный вход.

## Impact

- Новый локальный MCP-процесс на Node.js с официальным MCP SDK и библиотекой транспорта; схемы аргументов и структурированные результаты без зависимости от Dexie.
- Браузерный адаптер и подключение в `src/app/app.tsx`; существующие use cases, публичный экспорт feature и обновление состояния без обхода архитектурных границ.
- Новый репозиторный skill и инструкция подключения MCP; unit, протокольные и browser-level проверки, ручная проверка настоящего внутреннего браузера Codex.
- Уточнить продуктовые документы: AI-интеграция перестаёт быть полностью отложенной. Не добавляются аккаунты, облако, синхронизация, отдельная база, новые поля карточки, удаление проектов или массовые атомарные операции.
- Реализация начинается с проверки транспорта в целевом внутреннем браузере. Нельзя подменять её переносом сайта на localhost, сменой origin или доступом к данным другого браузера.
