# Design

## Context

База a8b 4115a5d 6874d 28643cfe2ba 2879a1e 4279b9c. Пользователь явно выбрал A 2026-10-29. Источник вида: docs/design/board-directions, направление a. Существующий React уже реализует сохранение, фокус и операции; прототип содержит отдельные демоданные и не переносится как приложение.

## Goals / Non-Goals

**Goals:** перенести визуальные решения в существующие компоненты, дать четыре колонки при 1280/1440, сохранить desktop/mobile и клавиатурные сценарии.

**Non-Goals:** смена модели, миграции данных, новые функции, повторный выбор концепции, внешние сервисы и зависимости.

## Decisions

1. Переиспользовать существующие React-компоненты и бизнес-операции. Менять DOM только ради семантики/компоновки; не копировать демо-JS. Это сохраняет проверенные отказы сохранения, сортировку и возврат фокуса.
2. Обновить единые CSS tokens и организовать стили читаемыми блоками. Тёплая светлая палитра, зелёный акцент, системный шрифт, мягкие метки с текстом и различимыми символами. Визуальные значения брать из выбранного A, а не создавать третью концепцию.
3. App bar: бренд и заголовок в первой строке с языком справа, навигация и действия во второй; на 320 px те же две строки. Длинный заголовок переносится. Сохранить выравнивание внешних границ контента app bar с main. Текущий e2e сравнивает левый край h1 с main, но это деталь старой композиции: обновить его на границы содержимого app-bar-inner. На desktop бренд слева, заголовок рядом, язык справа, как в A; небольшой знак бренда необязателен, если мешает компактности/семантике.
4. Четыре адаптивные колонки на desktop, минимально читаемая ширина при большем числе статусов и внутренний scroll. На mobile оставлять видимый край соседнего статуса. Меню/outline не обрезаются контейнером; проверить крайние и нижние карточки. Создание после списка — часть выбранного варианта A.
5. Компактные RU/EN сохраняют доступное имя, предупреждение о невозможности сохранить язык и существующие значения выбора. Помощь установки на mobile в потоке после рабочей области, desktop в углу; PWA update/restart поведение сохраняется.
6. Один дизайнер отвечает за UI, тесты компоновки и QA в назначенном дереве. Основной чат владеет OpenSpec, независимым review, интеграцией и доставкой. Одна функция — одна ветка codex/calm-board-design; отдельная интеграционная ветка для пакета не требуется.

## Risks / Trade-offs

- Просторные карточки требуют больше вертикального scroll; создание под списком ниже на длинном статусе → проверить достижимость и фокус после создания.
- Внутренний scroll может обрезать меню/outline → проверить первую/последнюю колонку, нижнюю карточку и 320 px, исправить в presentation без изменения операций.
- Общие CSS затрагивают каталог и служебные состояния → проверить их вид, полный npm run check и modal isolation.
- Chromium не заменяет реальные мобильные браузеры → явно записать непроверенные устройства в QA.
