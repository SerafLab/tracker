# Proposal

## Why

Просмотр большого набора скриншотов агентом увеличивает расход лимитов без обязательной пользы после каждого успешного прогона. Нужно отделить автоматическое сохранение изображений от их анализа моделью и сделать визуальный просмотр выборочным.

## What Changes

- Закрепить в проектных инструкциях отсутствие обязательного просмотра скриншотов после каждого прогона автоматических тестов.
- Использовать просмотр изображений при изменениях интерфейса, разборе конкретной ошибки с визуальной составляющей или по явному запросу пользователя. Выбирать относящиеся к задаче экраны, размеры и состояния вместо просмотра всей матрицы тестов.
- Согласовать это правило с маршрутизацией агентов, процессом дизайнера и планом ручной визуальной проверки. Не повторять уже выполненный просмотр того же результата без новой причины.
- В отчётах различать успешные автоматические проверки и фактически выполненную визуальную проверку, кратко указывая её область.
- Сохранить текущие автоматические тесты, создание скриншотов, локальный обязательный `npm run check`, pre-push hook и проверки GitHub. Перенос проверок исключительно в CI не входит в это изменение.

## Capabilities

### New Capabilities

Нет. Меняются инструкции процесса разработки, а не возможности приложения.

### Modified Capabilities

Нет. Изменение использует `skip_specs: true`: требования действующих продуктовых спецификаций не меняются.

## Impact

Планируемые изменения: `AGENTS.md`, `docs/agents/rules/agent-routing.md`, `docs/agents/designer.md` и `docs/manual-visual-qa.md`. Конфигурацию роли `.codex/agents/designer.toml` следует согласовать с общим правилом, если её формулировки допускают обязательный повторный просмотр всего набора.

Код приложения, тесты, зависимости, конфигурация Playwright и GitHub Actions не требуют изменений. Исторические записи проверок и чужие активные изменения OpenSpec сохраняются. Ожидается уменьшение лишнего анализа изображений; конкретный процент экономии не обещается и этим изменением не измеряется.
