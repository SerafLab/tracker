# Design

## Context

Мотивация и согласованный состав панели описаны в `proposal.md`. Сейчас `src/ui/app-bar.tsx` всегда показывает `LocaleSelector` и выделяет отдельную строку для `navigation` и `actions`. Доска передаёт кнопку возврата, меню проекта с единственным переименованием и создание статуса; каталог — создание проекта. Служебные состояния используют тот же AppBar без действий.

`LocaleSelector` уже сохраняет выбор независимо от базы проектов через `LocaleProvider`. `ActionMenu` в feature рассчитан на набор кнопок с `role=menu` и стрелочную навигацию; вставка обычного select нарушит этот контракт. Проверка архитектуры запрещает общему UI импортировать внутренние компоненты feature. `useModalOpen` изолирует шапку во время модальных диалогов.

Изменение затрагивает оболочку, локализацию и presentation, поэтому отдельный дизайн нужен. Действующие требования `application-shell` о двух строках desktop и прямом селекторе, а также `interface-language` о расположении селектора заменяются соответствующими дельтами. Требование о мобильной установочной подсказке сохраняется без изменения.

## Goals / Non-Goals

**Goals:**
- Общий AppBar владеет шестерёнкой, панелью настроек и её жизненным циклом, включая служебные состояния.
- Feature передаёт только доступные контекстные действия и существующий обработчик навигации; UI не получает доступа к хранилищу.
- Существующие диалоги создания и переименования сохраняют поведение с корректным возвратом фокуса к новым триггерам.

**Non-Goals:**
- Переработка карточек, статусов, остальных меню или экранов установки.
- Новые настройки, редактирование имени прямо в шапке, миграция данных, новый механизм маршрутизации.
- Сохранение старых props и параллельных способов доступа в шапке ради совместимости.

## Decisions

### 1. Контракт AppBar описывает назначение действий

Заменить slots `navigation/actions` на явные необязательные контракты: возврат в каталог, создание с локализованной подписью и ref триггера, переименование с ref шестерёнки. Доска подключает существующий `onReturn`, создание статуса и открытие `NameDialog`; каталог подключает создание проекта. Шапка сама рисует одинаковые плюс и шестерёнку. Служебные вызовы остаются без контекстных действий, настройки языка доступны по умолчанию.

На доске бренд — семантическая кнопка, использующая существующий обработчик навигации без перезагрузки. Его доступное имя включает EasyTrack и назначение «Все проекты». В каталоге и служебных состояниях бренд остаётся неинтерактивным: это предлагаемый технический default, поскольку там нет осмысленного возврата с доски. Альтернатива с отдельной кнопкой назад отвергнута согласованным решением.

### 2. Шестерёнка открывает немодальную панель настроек

Добавить небольшой компонент панели в `src/ui/`, не импортируя внутренний `ActionMenu` из feature. Использовать нативный Popover API, который уже применяется в приложении: панель в верхнем слое, обычный Tab-порядок, Escape и закрытие снаружи. Триггер имеет доступное название, `aria-expanded` и связь с панелью; сама панель имеет локализованное название «Настройки». Не назначать `role=menu` контейнеру с select.

На доске панель содержит кнопку «Переименовать проект» и подписанный выбор языка приложения; в каталоге и служебных состояниях — только язык. Сохранить существующие `LocaleProvider` и `LocaleSelector`, включая предупреждение о невозможности сохранить язык. Смена языка не закрывает панель и не сбрасывает фокус. Скрытая панель не оставляет доступных контролов или дубликатов селектора.

Перед запуском переименования закрыть панель; после завершения или отмены вернуть фокус к шестерёнке через существующий `returnFocus`. Любой модальный диалог закрывает настройки; изменения `useModalOpen` должны скрывать и top-layer панель, а не только делать header inert. При смене экрана настройки закрываются. Escape возвращает фокус к шестерёнке, внешнее нажатие сохраняет фокус на выбранной пользователем цели.

Альтернативы: модальный диалог настроек добавляет лишний шаг и требует исключения из запрета селектора в модалках; расширение существующего ActionMenu усложняет универсальный контракт ради одного составного элемента.

### 3. Адаптивная сетка вместо отдельного ряда действий

Desktop: `brand / minmax(0, 1fr) title / plus / gear`, с уменьшенными вертикальными отступами и общей минимальной высотой контролов 44 px. Действия группируются справа. Сохранить существующую границу мобильного layout 650 px как предлагаемый default. На телефоне первая строка — бренд слева, плюс и шестерёнка справа; вторая — заголовок на всю ширину. При отсутствии плюса его место не резервируется. Длинное название переносится, в том числе без пробелов; запрета на рост высоты текста нет.

Сохранить текущую палитру, выравнивание с workspace и прокрутку шапки вместе с документом. Удалить старые правила, скрывающие плюс до 360 px. Вынести нужные шапке SVG в общий UI или определить их там; не импортировать BoardIcon в обратном направлении из feature.

Альтернатива с одной строкой на телефоне отвергнута: название проекта снова будет зажато между брендом и действиями.

### 4. Иконки сохраняют понятное назначение

Плюс остаётся зелёным основным действием, шестерёнка — второстепенной. У контролов минимум 44 × 44 CSS px, локализованное доступное имя и подсказка при hover и focus; одного `title` недостаточно для гарантированной подсказки при клавиатурном фокусе. Названия плюса сохраняют семантику «Создать проект» и «Добавить статус», чтобы не менять контракт диалогов. Переводы новых строк добавить в RU/EN.

## Risks / Trade-offs

- Менее очевидное возвращение через бренд → подсказка назначения, доступное имя и явный focus-state.
- Плюс зависит от текущего экрана → контекстное название, подсказка и неизменные диалоги с названием создаваемого объекта.
- Общий язык рядом с настройкой проекта → отдельная подпись «Язык приложения» внутри панели.
- Top-layer панель может остаться доступной поверх модалки → закрывать при смене модального состояния; проверить создание, переименование и установочную подсказку.
- Существующие тесты ищут видимый combobox сразу после загрузки → обновить пользовательские сценарии открытия настроек в locale, app-bar, calm-board, PWA и card-priority проверках, не ослабляя проверки локализации и модальной изоляции.

## Migration Plan

Обновить контракт AppBar и все вызовы одним изменением, затем обновить проверки. Миграция данных и новые зависимости не нужны. Перед готовым PR выполнить `npm run check`, синхронизировать дельты и архивировать OpenSpec в той же ветке согласно правилам репозитория. Откат — возврат изменения кода и спецификаций; сохранённые данные и язык остаются совместимыми.
