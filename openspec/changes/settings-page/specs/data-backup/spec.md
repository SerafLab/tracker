# Spec Delta

## MODIFIED Requirements

### Requirement: Backup delivery
На устройстве с сенсорным основным вводом, где браузер умеет отправлять файлы, выгрузка SHALL открывать системное меню «Поделиться» с файлом копии. В остальных случаях файл SHALL скачиваться. Отмена системного меню пользователем SHALL не считаться ошибкой. Ошибка чтения данных SHALL показываться в диалоге с сообщением «Не удалось выгрузить резервную копию» и не изменять данные. После завершения, отмены или закрытия диалога ошибки фокус SHALL находиться на кнопке «Выгрузить резервную копию».

#### Scenario: User exports on a desktop browser
- **WHEN** пользователь выгружает копию в браузере компьютера с мышью
- **THEN** браузер скачивает файл с именем резервной копии

#### Scenario: User exports on a phone with file sharing
- **WHEN** пользователь выгружает копию на телефоне, где браузер поддерживает отправку файлов
- **THEN** открывается системное меню «Поделиться» с файлом резервной копии

#### Scenario: User cancels the share sheet
- **WHEN** пользователь закрывает системное меню «Поделиться» без выбора действия
- **THEN** сообщения об ошибке нет, данные не изменились, фокус находится на кнопке «Выгрузить резервную копию»

### Requirement: Backup file validation before restore
После выбора файла в «Восстановить из резервной копии» система SHALL полностью проверить файл, прежде чем показывать подтверждение или менять данные. Файл SHALL отклоняться целиком, без частичного или исправленного восстановления. Причины отказа: не JSON, нет маркера EasyTrack, неверная структура или значения, нарушена целостность. Отказ SHALL показываться в диалоге и не изменять данные; закрытие диалога SHALL возвращать фокус к кнопке «Восстановить из резервной копии».

#### Scenario: User selects an unrelated file
- **WHEN** пользователь выбирает файл, который не является JSON или не содержит маркера резервной копии EasyTrack
- **THEN** диалог сообщает «Файл не является резервной копией EasyTrack или повреждён», а проекты и открытая страница настроек не меняются

#### Scenario: User selects a copy from a newer application
- **WHEN** пользователь выбирает копию EasyTrack с версией формата больше поддерживаемой
- **THEN** диалог сообщает «Копия создана более новой версией EasyTrack — обновите приложение», а данные не меняются

#### Scenario: User cancels file selection
- **WHEN** пользователь закрывает выбор файла, ничего не выбрав
- **THEN** ни диалога, ни изменений нет, фокус находится на кнопке «Восстановить из резервной копии»

### Requirement: Restore confirmation with comparison
Для корректной копии система SHALL показать модальный диалог подтверждения. Диалог сравнивает число проектов, карточек и заметок сейчас и в копии, показывает дату и время выгрузки копии в языке интерфейса и предупреждает, что все текущие данные проектов будут заменены. Диалог SHALL предлагать «Сначала выгрузить текущие данные», «Отмена» и «Заменить». «Отмена» SHALL закрывать диалог без изменений и возвращать фокус к кнопке «Восстановить из резервной копии».

#### Scenario: User reviews an older copy
- **WHEN** сейчас 3 проекта, 24 карточки и 51 заметка, а выбранная копия от 1 ноября 2026 года содержит 2 проекта, 19 карточек и 40 заметок
- **THEN** диалог показывает обе тройки чисел, дату выгрузки копии и предупреждение о полной замене

#### Scenario: User exports current data before replacing
- **WHEN** пользователь в диалоге выбирает «Сначала выгрузить текущие данные»
- **THEN** выполняется обычная выгрузка текущих данных, а диалог остаётся открытым с прежней копией

#### Scenario: User restores an empty copy
- **WHEN** выбранная копия не содержит проектов, а сейчас проекты есть
- **THEN** диалог показывает 0 проектов в копии и тем же подтверждением позволяет заменить данные

### Requirement: Atomic restore with full replacement
После «Заменить» все данные проектов SHALL заменяться содержимым копии одной транзакцией без объединения; последний открытый проект SHALL сбрасываться. Несохранённых черновиков в этот момент нет: страница настроек открывается только через защиту черновиков. Успех SHALL открывать каталог и показывать уведомление «Данные восстановлены из резервной копии». Ошибка записи SHALL оставлять прежние данные без изменений и сообщаться в диалоге.

#### Scenario: User replaces data
- **WHEN** пользователь открыл настройки с доски проекта и подтверждает восстановление корректной копии
- **THEN** открывается каталог только с проектами из копии, прежних проектов нет, показано уведомление, а после перезагрузки страницы открывается каталог с теми же данными

#### Scenario: User has an unsaved card draft
- **WHEN** пользователь с несохранённым черновиком карточки нажимает шестерёнку, чтобы восстановить копию
- **THEN** обычный вопрос о несохранённых изменениях появляется до открытия настроек; при выборе «Остаться» данные, карточка и черновик не меняются

#### Scenario: Write fails during restore
- **WHEN** запись в хранилище прерывается ошибкой во время замены
- **THEN** все прежние проекты, карточки и заметки сохраняются без изменений, страница настроек остаётся открытой, а диалог сообщает «Не удалось восстановить данные»
