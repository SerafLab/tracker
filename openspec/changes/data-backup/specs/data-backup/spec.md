# Spec Delta

## Purpose

Позволяет вручную сохранить все данные проектов этого устройства в файл резервной копии и позже восстановить их с полной заменой текущих данных. Так локальные данные переживают их потерю в браузере.

## ADDED Requirements

### Requirement: Backup export of all project data
Выгрузка SHALL создавать один файл резервной копии со всеми проектами, статусами, карточками (название, описание, важность, срочность, расположение) и заметками (текст, даты создания и изменения) этого устройства. Настройки устройства SHALL не входить в копию: тему, язык, порядок заметок, последний открытый проект и признак приглашения к установке копия не содержит. Выгрузка SHALL быть доступна и без проектов, а также SHALL не изменять данные.

#### Scenario: User exports populated data
- **WHEN** пользователь с несколькими проектами, карточками и заметками выбирает «Выгрузить резервную копию»
- **THEN** создаётся файл, после восстановления которого на чистом устройстве проекты, статусы, порядок статусов, карточки, их признаки и расположение, описания и заметки с датами совпадают с исходными

#### Scenario: User exports without projects
- **WHEN** в каталоге нет проектов и пользователь выбирает «Выгрузить резервную копию»
- **THEN** создаётся корректная резервная копия без проектов

#### Scenario: Device settings stay out of the copy
- **WHEN** пользователь выбрал английский язык, чернильную тему и порядок «сначала старые», а затем выгрузил копию
- **THEN** копия не содержит этих настроек, и её восстановление не меняет язык, тему и порядок заметок устройства

### Requirement: Backup file identity
Файл резервной копии SHALL быть читаемым JSON с именем `easytrack-backup-YYYY-MM-DD-HHmm.json` по локальному времени выгрузки. Файл SHALL содержать маркер формата EasyTrack, целую версию формата, время выгрузки в UTC, версию приложения и короткий SHA коммита сборки. Текущая версия формата SHALL быть 1.

#### Scenario: User exports twice in one day
- **WHEN** пользователь выгружает копию 6 ноября 2026 года в 14:30 и снова в 18:05 по местному времени
- **THEN** файлы называются `easytrack-backup-2026-11-06-1430.json` и `easytrack-backup-2026-11-06-1805.json`

#### Scenario: User opens the file in a text editor
- **WHEN** пользователь открывает выгруженный файл как текст
- **THEN** он видит JSON с маркером формата, версией формата 1, временем выгрузки, версией и SHA сборки и данными проектов

### Requirement: Backup delivery
На устройстве с сенсорным основным вводом, где браузер умеет отправлять файлы, выгрузка SHALL открывать системное меню «Поделиться» с файлом копии. В остальных случаях файл SHALL скачиваться. Отмена системного меню пользователем SHALL не считаться ошибкой. Ошибка чтения данных SHALL показываться в диалоге с сообщением «Не удалось выгрузить резервную копию» и не изменять данные.

#### Scenario: User exports on a desktop browser
- **WHEN** пользователь выгружает копию в браузере компьютера с мышью
- **THEN** браузер скачивает файл с именем резервной копии

#### Scenario: User exports on a phone with file sharing
- **WHEN** пользователь выгружает копию на телефоне, где браузер поддерживает отправку файлов
- **THEN** открывается системное меню «Поделиться» с файлом резервной копии

#### Scenario: User cancels the share sheet
- **WHEN** пользователь закрывает системное меню «Поделиться» без выбора действия
- **THEN** сообщения об ошибке нет, данные не изменились, фокус находится на шестерёнке

### Requirement: Backup file validation before restore
После выбора файла в «Восстановить из резервной копии» система SHALL полностью проверить файл, прежде чем показывать подтверждение или менять данные. Файл SHALL отклоняться целиком, без частичного или исправленного восстановления. Причины отказа: не JSON, нет маркера EasyTrack, неверная структура или значения, нарушена целостность. Отказ SHALL показываться в диалоге и не изменять данные.

#### Scenario: User selects an unrelated file
- **WHEN** пользователь выбирает файл, который не является JSON или не содержит маркера резервной копии EasyTrack
- **THEN** диалог сообщает «Файл не является резервной копией EasyTrack или повреждён», а проекты и открытый экран не меняются

#### Scenario: User selects a copy from a newer application
- **WHEN** пользователь выбирает копию EasyTrack с версией формата больше поддерживаемой
- **THEN** диалог сообщает «Копия создана более новой версией EasyTrack — обновите приложение», а данные не меняются

#### Scenario: User cancels file selection
- **WHEN** пользователь закрывает выбор файла, ничего не выбрав
- **THEN** ни диалога, ни изменений нет, фокус находится на шестерёнке

### Requirement: Backup integrity rules
Резервная копия SHALL считаться повреждённой, если нарушено хотя бы одно правило:
- повторяется идентификатор внутри проектов, статусов, карточек или заметок;
- статус, карточка или заметка ссылается на отсутствующего владельца;
- позиции статусов проекта или карточек статуса не идут подряд с нуля;
- карточки статуса нарушают порядок групп;
- обязательное имя пустое;
- дата не является корректной датой ISO 8601.

#### Scenario: Card refers to a missing status
- **WHEN** пользователь выбирает копию, где карточка ссылается на статус, которого нет в копии
- **THEN** копия отклоняется как повреждённая, данные не меняются

#### Scenario: Positions have a gap
- **WHEN** пользователь выбирает копию, где у статусов проекта позиции 0, 1 и 3
- **THEN** копия отклоняется как повреждённая без перенумерации

### Requirement: Restore confirmation with comparison
Для корректной копии система SHALL показать модальный диалог подтверждения. Диалог сравнивает число проектов, карточек и заметок сейчас и в копии, показывает дату и время выгрузки копии в языке интерфейса и предупреждает, что все текущие данные проектов будут заменены. Диалог SHALL предлагать «Сначала выгрузить текущие данные», «Отмена» и «Заменить». «Отмена» SHALL закрывать диалог без изменений и возвращать фокус к шестерёнке.

#### Scenario: User reviews an older copy
- **WHEN** сейчас 3 проекта, 24 карточки и 51 заметка, а выбранная копия от 1 ноября 2026 года содержит 2 проекта, 19 карточек и 40 заметок
- **THEN** диалог показывает обе тройки чисел, дату выгрузки копии и предупреждение о полной замене

#### Scenario: User exports current data before replacing
- **WHEN** пользователь в диалоге выбирает «Сначала выгрузить текущие данные»
- **THEN** выполняется обычная выгрузка текущих данных, а диалог остаётся открытым с прежней копией

#### Scenario: User restores an empty copy
- **WHEN** выбранная копия не содержит проектов, а сейчас проекты есть
- **THEN** диалог показывает 0 проектов в копии и тем же подтверждением позволяет заменить данные

### Requirement: Atomic restore with full replacement
После «Заменить» система SHALL применить защиту несохранённых черновиков. Если пользователь остаётся, восстановление SHALL отменяться. Затем все данные проектов SHALL заменяться содержимым копии одной транзакцией без объединения; последний открытый проект SHALL сбрасываться. Успех SHALL открывать каталог и показывать уведомление «Данные восстановлены из резервной копии». Ошибка записи SHALL оставлять прежние данные без изменений и сообщаться в диалоге.

#### Scenario: User replaces data
- **WHEN** пользователь подтверждает восстановление корректной копии на доске проекта
- **THEN** открывается каталог только с проектами из копии, прежних проектов нет, показано уведомление, а после перезагрузки страницы открывается каталог с теми же данными

#### Scenario: User has an unsaved card draft
- **WHEN** пользователь с несохранённым черновиком карточки выбирает «Заменить»
- **THEN** появляется обычный вопрос о несохранённых изменениях; при выборе «Остаться» данные и черновик не меняются

#### Scenario: Write fails during restore
- **WHEN** запись в хранилище прерывается ошибкой во время замены
- **THEN** все прежние проекты, карточки и заметки сохраняются без изменений, а диалог сообщает «Не удалось восстановить данные»

### Requirement: Backup format compatibility
Каждое изменение сохраняемых данных, влияющее на содержимое копии, SHALL повышать версию формата. Приложение SHALL принимать копии всех прежних версий формата и преобразовывать их только вперёд до текущей версии перед проверкой целостности. Выгрузка SHALL всегда записывать текущую версию.

#### Scenario: User restores a copy made by an earlier release
- **WHEN** после выпуска с версией формата 2 пользователь выбирает копию версии 1
- **THEN** копия преобразуется к версии 2, проходит обычную проверку и подтверждение и восстанавливает все данные версии 1

### Requirement: Backup is a user-only action
Выгрузка и восстановление SHALL быть доступны только через интерфейс приложения. Набор инструментов агента SHALL не меняться этим изменением.

#### Scenario: Agent lists available tools
- **WHEN** агент в поддерживаемом браузере запрашивает инструменты EasyTrack
- **THEN** среди них нет выгрузки или восстановления резервной копии
