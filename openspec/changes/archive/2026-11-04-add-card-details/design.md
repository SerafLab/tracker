# Design

## Context

Мотивация описана в `proposal.md`. Сейчас `CardInput` содержит название и два признака, Dexie использует схему v2, заметок нет. `CardDialog` обслуживает создание и редактирование. `Workspace` различает каталог и доску, а успешные мутации вызывают `showBoard`, поэтому прямое повторение этого подхода закроет будущую страницу карточки.

Hash-навигацией реально владеет `src/app/app.tsx`, как закреплено ADR-0004; React Router, упомянутый в раннем technical-plan, сейчас не используется. Представление и Zustand зависят от use cases, домена и порта репозитория; Dexie остаётся адаптером. Данные локальны для origin и браузера.

## Goals / Non-Goals

**Goals:** расширить существующий feature без второго источника данных и двух реализаций редактора, обеспечить транзакционные сохранения, понятные ошибки и управляемую навигацию с черновиками.

**Non-Goals:** общий редактор документов, история версий текста, инфраструктура совместной работы, рефакторинг всего приложения или поддержка прежних внутренних API. Остальные границы перечислены в proposal.

## Decisions

### 1. Один адрес карточки, два представления

Добавить маршрут `#project/<projectId>/card/<cardId>` и состояние подробностей с подтверждёнными данными карточки, её проекта, статуса и заметок. Проверять принадлежность карточки проекту при чтении. Переход с доски создаёт запись истории с тем же адресом и признаком представления `panel`; прямой адрес, новая вкладка и перезагрузка, где такого признака нет, открывают полную страницу. Признак не входит в ссылку и не хранится в IndexedDB. Отсутствующая карточка показывает понятное состояние с возвратом на существующую доску, отсутствующий проект — переход к каталогу. Нельзя подставить карточку другого проекта.

Единый владелец навигации в app обрабатывает каталог, доску, панель, страницу и pending destination без отдельного роутера. Первое открытие карточки с доски делает `pushState`; переключение A → B → C в открытой панели делает `replaceState`, поэтому Back возвращает к записи доски. «Открыть на всю страницу» добавляет запись с тем же URL и признаком `page`; Back от неё восстанавливает панель последней карточки, затем доску. При открытии прямой ссылки «К доске» использует явный адрес проекта, а не предполагает наличие предыдущей записи. Обрабатывать `popstate` и изменение hash через единый механизм; индексированные записи позволяют перехватывать Back/Forward, восстанавливать текущую запись до решения пользователя и применять исходный переход один раз. Быстрые повторные переходы не создают несколько диалогов; устаревшие async-загрузки не заменяют более новый экран.

Общий редактор и черновики живут выше переключателя представлений. Переход панели в полную страницу сохраняет их без размонтирования и без guard, так как карточка и черновик остаются теми же. При перезагрузке обычный `beforeunload` защищает dirty-черновик настолько, насколько это позволяет браузер; после разрешённой перезагрузки открывается полная страница с последними подтверждёнными данными. Альтернатива — два разных URL или параметр `panel=1` — делала бы скопированную ссылку зависимой от временного контекста доски.

### 2. Доска остаётся рабочей рядом с панелью

Сохранить `li` и самостоятельные стрелки/меню. Семантическая ссылка на адрес карточки с доступным именем по названию покрывает свободную площадь через CSS; остальные контролы — её siblings. Внутренний переход перехватывается приложением и открывает панель; обычное открытие ссылки в новой вкладке ведёт на полную страницу. Не делать кнопку вокруг кнопок. Enter на ссылке открывает панель, стрелки и пункты меню выполняют только свои действия, в том числе недоступные стрелки не превращаются в ссылку. Меню «Редактировать» открывает ту же панель; отдельный edit-dialog удаляется.

На широком экране панель размещается рядом с доской и имеет самостоятельную прокрутку; доска остаётся смонтированной, прокручиваемой и интерактивной. Смена выбранной карточки не сбрасывает прокрутку доски. Панель не является модальным диалогом на широком экране: фокус переходит к её заголовку при открытии, но пользователь может перейти к доске и открыть другую карточку. На узком экране панель занимает весь экран, фон доски временно недоступен для фокуса, закрытие возвращает к доске. Ширина адаптируется без горизонтального переполнения документа; горизонтальная прокрутка статусов остаётся внутри доски. Альтернатива — модальный overlay на десктопе — мешала бы переключению карточек одним действием.

Внутри той же ссылки показывать сохранённое описание из snapshot доски, только если в нём есть непробельный текст. Ограничить предпросмотр тремя видимыми строками средствами CSS, сохраняя переносы обычного текста; не обрезать хранимое значение. Не применять `linkify-react` в предпросмотре: вложенная ссылка нарушила бы единое действие открытия карточки. После успешного сохранения полей подтверждённый snapshot доски показывает обновлённый текст без закрытия панели; при ошибке записи прежний предпросмотр остаётся неизменным. Заметки на доске не отображаются.

### 3. Основные поля и заметки имеют разные контракты

`Card` получает обязательную строку `description`, пустую по умолчанию; `CardInput` — четыре редактируемых поля. Создание остаётся компактным диалогом с названием и двумя признаками; описание присваивается `''`, заполняется в подробностях. Это явный минимальный default, а не вторая форма подробного редактирования.

Новая сущность `Note`: `id`, `cardId`, `text`, `createdAt`, необязательный `updatedAt`. UUID и ISO UTC timestamps выдаёт use case через существующие зависимости `createId`/`now`; редактирование сохраняет `createdAt`, устанавливает `updatedAt` только при фактической правке. Пустой после trim текст не сохраняется, внутренние переносы и пробелы сохраняются. История идёт от старых записей к новым, при равном времени — по id; редактирование её не переставляет. Даты отображляются через `Intl.DateTimeFormat` в текущем языке и локальном часовом поясе пользователя. Это личные заметки, авторства и веток ответов нет.

Порт получает чтение деталей с проверкой проекта и операции create/update/delete note. Операции заметок проверяют существование карточки; правка/удаление проверяют принадлежность заметки этой карточке. Основные поля сохраняются одной транзакцией вместе с изменением priority order. Описание и заметки сами не меняют порядок. Удаление карточки, всех её заметок и перенумерация оставшихся карточек — одна транзакция. Перенос сохраняет описание и заметки без перепривязки.

### 4. Обновлять подтверждённые данные по контексту действия

Zustand хранит подтверждённые snapshot доски и выбранной карточки, React — черновики и их исходные значения. Успешная мутация обновляет оба подтверждённых snapshot по контексту, а не безусловно вызывает `showBoard`. Явное действие «Сохранить» записывает четыре основных поля и оставляет текущую панель или страницу открытой. При отказе записи остаются прежние подтверждённые данные и введённые черновики. Сохранение заметки само по себе тоже оставляет подробности открытыми. Обновление списка заметок не сбрасывает несохранённые основные поля и наоборот.

В подробностях одновременно открыт один редактор заметки: новый либо существующий. Переключение редактора при dirty проходит через тот же guard. Сохраняемые мутации защищены от повторной отправки. После добавления заметки очищается только её черновик; после правки закрывается её редактор. У сохранённой заметки вторичные действия представлены иконками карандаша и корзины из общего визуального языка приложения, с локализованными `aria-label`, видимым фокусом и удобными для касания областями. Добавление, сохранение и отмена редактирования заметки остаются текстовыми действиями. Удаление требует отдельного подтверждения с идентификацией записи и возвращает фокус к соседней записи или добавлению.

### 5. Защита черновиков имеет точную границу

Dirty сравнивает поля с последним подтверждённым snapshot и учитывает новый/изменённый текст заметки. App регистрирует у общего редактора обработчики проверки, сохранения и сброса. Закрытие панели, переключение на другую карточку, переходы по бренду и внутренним ссылкам, Back/Forward и управляемая кнопка обновления приложения сначала показывают один диалог: «Сохранить и выйти», «Выйти без сохранения», «Остаться». При отсутствии dirty переход немедленный. Переход панели в полную страницу той же карточки сохраняет черновики и не требует этого диалога.

Для «Сохранить и выйти» сначала сохранять основные поля, затем активный черновик заметки. Это последовательные самостоятельные операции, как и явные кнопки в подробностях. Если часть уже сохранена отдельной кнопкой, guard обрабатывает только оставшийся dirty-черновик. Если вторая операция не удалась, выбранный переход или переключение не происходит, подтверждённые поля остаются сохранёнными, текст заметки остаётся доступным с ошибкой. Повторная попытка не создаёт дубликат и не повторяет уже подтверждённую операцию. При валидационной ошибке переход также отменяется. «Выйти без сохранения» сбрасывает только оставшиеся черновики; «Остаться»/Escape ничего не теряют.

Для закрытия вкладки и нативной перезагрузки устанавливается `beforeunload` только при dirty: браузер сам показывает стандартное предупреждение, без обещания собственного диалога или сохранения при закрытии. Управляемое обновление PWA активирует worker/reload только после guard. Аварийное завершение процесса и forced restart после закрытия stale DB не гарантируют сохранение черновика; нельзя пытаться писать через закрытое соединение.

### 6. Обычный текст, общий shell и локализация

Использовать textarea, обычный React text rendering и `linkify-react` для распознавания только абсолютных HTTP/HTTPS URL в отображаемом описании и заметках; не интерпретировать HTML/Markdown и не использовать `dangerouslySetInnerHTML`. Веб-ссылки открываются отдельно с `noopener noreferrer`, чтобы не уводить страницу с черновиком. Адаптер и настройка URL описаны в [официальной документации React](https://linkify.js.org/docs/linkify-react.html) и [options](https://linkify.js.org/docs/options.html): фильтр HTTP/HTTPS, отключение email, target/rel. Выбор версии проверяется по актуальной совместимости при реализации; отдельный формат хранения не нужен. Альтернатива rich-text editor избыточна согласованному обычному тексту.

На полной странице AppBar показывает сохранённое название карточки как единственный h1, настройки языка и бренд с переходом к каталогу через guard. Под AppBar перед формой — компактный возврат «К доске» с названием проекта, стрелкой, удобной областью касания и видимым фокусом. В открытой панели AppBar остаётся в контексте доски, а панель получает собственный заголовок, действия закрытия и «Открыть на всю страницу». На полной странице создание статуса и переименование проекта не показываются. На 320 px длинный текст и ссылки переносятся, формы и история не создают горизонтального переполнения. Все подписи, ошибки, даты и подтверждения RU/EN; пользовательский текст не переводится.

## Risks / Trade-offs

- Перехват history и повторные async-запросы могут терять маршрут или неверно восстановить представление → browser-тесты Back/Forward, прямого адреса, перезагрузки панели, отмены и ошибки сохранения; один владелец переходов.
- Последовательное сохранение при уходе может завершиться частично → явный контракт подтверждённых частей и проверка повторной попытки без дублей.
- Будущий MCP change использует старый `CardInput` и обновление доски → перед совместной реализацией согласовать его контракты; не менять его артефакты или добавлять MCP в это изменение.
- Большой текст и узкая доска при открытой панели могут затруднить обзор → самостоятельная прокрутка панели, горизонтальная прокрутка статусов внутри доски, полноэкранные подробности на мобильном и визуальная проверка размеров; пагинация и лимиты не добавляются без измеренной необходимости.
- `show-recent-card-notes` описывает открытие страницы карточки → перед совместной реализацией согласовать его контракт с открытием панели, не меняя артефакты другого изменения в этом обновлении.

## Migration Plan

1. Добавить схему Dexie v3 с `notes: 'id, cardId, [cardId+createdAt]'`; существующие stores/индексы сохранить. В upgrade атомарно присвоить карточкам `description: ''`, сохранив имена, связи, flags и position; notes первоначально пуст.
2. Проверить обновление реальных v1 (через существующую v2) и v2, повторное открытие, откат транзакции при ошибке и `versionchange` старой вкладки. Тест с искусственной newer v3 поднять выше новой актуальной версии.
3. Выпустить обычным PWA-путём с существующим предложением обновления. Не активировать обновление поверх dirty-редактора без решения пользователя.
4. При сбое upgrade транзакция откатывается и показывается ошибка хранилища. После успешного upgrade откат на старый исполняемый код не поддерживается: восстановление — исправляющий релиз с этой или следующей схемой, без удаления пользовательской базы.
