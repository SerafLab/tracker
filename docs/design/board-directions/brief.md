# Доска EasyTrack: два направления для выбора

Статус: интерактивные предложения, **направление ещё не выбрано**. Production UI не изменён. Режим Impeccable: Operate.

## Открыть

После `npm run dev -- --host 127.0.0.1 --port 4184 --strictPort`:

- [Общий preview](http://127.0.0.1:4184/tracker/docs/design/board-directions/index.html)
- [A — Спокойная доска](http://127.0.0.1:4184/tracker/docs/design/board-directions/index.html?direction=a)
- [B — Чёткий порядок](http://127.0.0.1:4184/tracker/docs/design/board-directions/index.html?direction=b)

Нужен путь с `index.html`: открытие только каталога может попасть на Vite fallback. Прототип написан на HTML/CSS/JS, не требует новых зависимостей. Файлы `index.html`, `preview.css`, `preview.js` находятся рядом с этим brief.

Тёмная верхняя панель — средство сравнения **вне интерфейса EasyTrack**. Она объясняет статус демонстрации, переключает варианты и сбрасывает пример. Переключение A/B сохраняет внесённые изменения, перезагрузка сбрасывает их. Содержимое вымышленное, одинаковое для обоих вариантов.

## Что увидели в текущем интерфейсе

Текущий UI запущен и осмотрен в браузере. При 1440 px ограничение ширины вместе с фиксированными колонками обрезает четвёртый статус. Контейнеры статусов и карточек создают два слоя рамок. Название проекта, навигация, язык и действия воспринимаются как почти равнозначные элементы. Новые варианты делают ширину рабочей области полезнее и отделяют контекст проекта от действий.

## Варианты

| | A — Спокойная доска | B — Чёткий порядок |
| --- | --- | --- |
| Композиция | Просторная app bar в два ряда: идентичность и название сверху, навигация и действие ниже | Компактная однорядная app bar на широком экране; на телефоне два ряда |
| Рабочая область | Тёплый фон; самостоятельные светлые карточки без контейнеров вокруг колонок | Единое белое поле; колонки и карточки разделены тонкими линиями |
| Типографика | Название проекта 27 px, названия карточек 15 px | Название проекта 21 px, названия карточек 14 px; плотнее по вертикали |
| Признаки | Небольшие текстовые метки с мягким фоном; два разных символа | Текстовые метки без фона; те же символы и смысл |
| Цвет | Тёплые нейтрали и приглушённый зелёный для действий | Холодная светлая app bar и синий для действий |
| Сильная сторона | Легко выделить отдельную карточку и вернуться к личному делу без ощущения перегруженности | Больше содержимого видно одновременно, проще сравнивать списки |
| Компромисс | Высота карточек требует больше вертикальной прокрутки | Меньше пространственного разделения, длинный список воспринимается плотнее |

**Рекомендация дизайнера: A** для текущего персонального сценария. Отдельная карточка здесь — единица внимания. B стоит выбрать, если приоритет — быстро просматривать много объектов и экономить высоту экрана. Это рекомендация, не зафиксированный выбор.

## Сохранённые функции

- Проект, пользовательские статусы и карточки; четыре колонки в исходном примере.
- Создание, переименование и перестановка статусов. Удаление непустого статуса заблокировано с объяснением.
- Название и два независимых признака карточки; все четыре комбинации есть в первом статусе.
- Стабильный порядок: оба признака → важная → срочная → без признаков. Создание, перенос и реальная смена признаков добавляют в конец группы; переименование сохраняет место.
- Видимые стрелки на каждой карточке, в том числе отключённые граничные стрелки. Через меню можно выбрать любой другой статус.
- Контекстные меню карточки, статуса и проекта. Удаление карточки или пустого статуса требует подтверждения.
- Возврат в каталог и открытие проекта. Создание проекта работает на общих демонстрационных данных.
- Единственный селектор RU/EN в app bar. Пользовательские названия не переводятся. Фон недоступен при открытом диалоге.
- Модальное редактирование на desktop и нижний лист на телефоне. Escape, отмена, валидация пустого имени, фокус при открытии и возврат после закрытия.

Нет выдуманных сроков, заметок, поиска, фильтров, аккаунтов или дополнительных полей. `PRODUCT.md` явно отличает текущее поведение от roadmap.

## Явно предлагаемые визуальные изменения

Это предложения для будущей реализации после выбора, а не уже утверждённые контракты:

1. Увеличить полезную ширину: четыре колонки помещаются на 1280/1440 px. На телефоне горизонтальный скролл остаётся, край соседней колонки подсказывает продолжение.
2. Перенести «Добавить карточку» под список. Результат естественно читается как продолжение списка, но при большом числе карточек действие окажется ниже. Если частое создание важнее спокойной композиции, сохранить его у заголовка при реализации выбранного варианта.
3. Показывать количество карточек коротким числом рядом со статусом и компактный RU/EN вместо полного названия языка. Доступное имя селектора сохранено.
4. На ширине 320 px убрать только вспомогательные пиктограммы у «Все проекты» и «Добавить статус», сохранив названия и полноценные зоны нажатия. Стрелки карточек всегда видимы.
5. На телефоне расположить помощь по установке в потоке после доски: фиксированная кнопка перекрывала карточки. На desktop она остаётся в нижнем углу. В прототипе диалог прямо сообщает, что установка демонстрации недоступна.
6. Небольшой знак рядом с EasyTrack — предложение внутри вариантов, а не утверждённый бренд-актив.

App bar остаётся светлой, прокручивается с документом и на 320 px имеет два ряда компоновки. Тёмная панель сравнения в это ограничение не входит.

Проверено отдельной страницей Chromium через Playwright, без использования пользовательских данных и без управления браузерной вкладкой основного чата.

| --- | --- |
| A/B, 320/390/1280/1440 px | Нет горизонтального переполнения страницы; доска скроллится внутри рабочей области |
| A/B, RU/EN, 320/390 px | Все восемь сочетаний прошли интерактивный сценарий |

| Создание карточки | Пустое имя даёт ошибку; признаки доступны с клавиатуры; новая карточка в конце приоритетной группы; фокус возвращается к созданию |
| Редактирование | Название и признаки редактируются совместно; переименование сохраняет место; фокус возвращается в меню карточки |

| Размеры целей | Кнопки действий, меню и стрелки — минимум 44 px по высоте; иконки — 44×44; селектор — 44 px по высоте |

Применены актуальные [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). ### Ограничения

Это живой макет внешнего вида, не замена production: нет IndexedDB, сохранения языка/данных после reload, service worker, установки, моделирования сетевых/дисковых ошибок или асинхронного сохранения. Подсказка установки намеренно честно обозначает это. Полный `npm run check` выполняет основной чат. Safari, реальные iPhone/Android и экранная клавиатура на устройствах не проверялись. Не создавать DESIGN.md и не переносить эти стили в приложение до выбора пользователя.

## Применение Impeccable

Прочитаны `SKILL.md`, `init`, `new-work`, `operate`, `craft-floor`. Context загружен один раз, durable product context записан в `PRODUCT.md` из согласованного brief и источников репозитория. Интервью не дублировалось: субагент готовит варианты по заданию основного чата. Hooks, глобальные настройки и вложенные субагенты не использовались.

Concept seed: `seed:199702e2d1b48a26`, режим Operate. Для данного этапа явное требование пользователя — два интерактивных варианта на общем состоянии до выбора — имеет приоритет над стандартной страницей выбора скилла. Новый визуальный стандарт не записан. Заимствование ограничено типографикой, палитрой, плотностью и способом выделения карточки; привычные навигация и действия сохранены.
