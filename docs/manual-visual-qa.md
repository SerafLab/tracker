# План ручной визуальной проверки

Этот план относится к визуальному редизайну доски проектов (`redesign-project-board-ui`). Он дополняет автоматические тесты, а не заменяет их: `npm run test:production` проверяет операции и сохранность данных, а здесь проверяются реальные размеры, визуальная и keyboard-подача интерфейса.

## Подготовка

1. Запустите приложение через `npm run dev` либо откройте опубликованную версию.
2. Используйте отдельный профиль браузера, окно инкогнито или тестовое устройство. Не очищайте IndexedDB с личными данными ради этой проверки.
3. Проверьте три viewport в актуальном Chrome:
   - desktop — `1280 × 900` или шире;
   - mobile narrow — `320 × 568`;
   - mobile regular — `390 × 844`.
4. Для сценариев с заполненной доской создайте тестовый проект «Manual QA», статусы «Идеи», «В работе», «Завершено» и хотя бы одну карточку в «Идеи».

## Примечание о storage error

В обычном пользовательском интерфейсе нет кнопки, которая намеренно ломает IndexedDB или сохранение. Не отключайте хранилище и не удаляйте реальные данные ради этого сценария. Сейчас S-01 подтверждён автоматическими RTL-тестами; ручную часть выполняйте только в отдельном тестовом профиле, если есть безопасный способ воспроизвести ошибку.

## Визуальный чек-лист

- Кнопки-иконки и основные touch controls имеют фактический размер не меньше `44 × 44 px` (при сомнении проверьте размер в Chrome DevTools).
- Акцентный teal применяется к основному действию и focus state, а не кодирует смысл статусов.
- Текст, ошибка и disabled action различимы без опоры только на цвет.
- На заполненных каталогах и досках нет постоянно раскрытых технических форм.
- Отступы, радиусы и тени согласованы: поверхности border-first, тень только у приподнятых/интерактивных карточек.
- Нет новых фильтров, drag-and-drop, «completed»-семантики или других функций за пределами модели проект → статус → карточка.
