# Design

## Context

Мотивация описана в `proposal.md`. `npm run check` проверяет архитектуру, запускает Vitest, сборку и Playwright. В браузерных тестах есть вызовы `page.screenshot`, сохраняющие PNG для разных размеров, языков и состояний. В исследованных тестах нет отправки изображений модели или сравнения с эталоном через `toHaveScreenshot`.

`AGENTS.md` задаёт обязательные проверки, `docs/agents/rules/agent-routing.md` распределяет ответственность за приёмку, `docs/agents/designer.md` и `.codex/agents/designer.toml` требуют проверки отрисованного интерфейса при работе дизайнера. `docs/manual-visual-qa.md` содержит матрицу ручных сценариев и исторический результат просмотра скриншотов. Правило выбора изображений должно быть согласовано между этими документами.

Это сквозное изменение процесса агента в нескольких документах; дизайн нужен для единой трактовки области просмотра и ответственности.

## Goals / Non-Goals

**Goals:**

- Сделать решение об открытии изображений зависимым от задачи, а не от факта завершения тестов или наличия PNG.
- Сохранить проверку реальной отрисовки при изменении интерфейса и прозрачное описание фактически проверенного результата.
- Позволить основному чату использовать результаты выборочной проверки исполнителя без обязательного повторного просмотра.

**Non-Goals:**

- Менять команды, хуки, расписание или состав автоматических проверок.
- Добавлять переключатели генерации снимков, хранение CI-артефактов, эталонные изображения или AI-сервис анализа.
- Менять продуктовые спецификации, предметный словарь, исторические отчёты либо задачи других активных изменений.

## Decisions

### 1. Общее правило находится в AGENTS.md

Добавить краткое правило: сохранённые скриншоты не требуется открывать после каждого прогона. Допустимые основания для выборочного просмотра — изменение интерфейса, диагностика конкретной визуальной ошибки или запрос пользователя. Ошибка сборки или обычного теста сама по себе не требует просмотра изображений: сначала используются текст ошибки и относящийся к нему код.

Остальные документы ссылаются на это правило и уточняют собственную ответственность. Альтернатива — независимые инструкции в каждом документе — повышает риск расхождений.

### 2. Область просмотра следует изменению или ошибке

При изменении интерфейса проверяются затронутые экраны и состояния. Для адаптивной вёрстки выбираются относящиеся к изменению desktop/mobile-размеры; языки, длинный текст, фокус и специальные состояния добавляются, когда они затронуты. Для конкретной ошибки сначала выбирается воспроизводящий её снимок или участок экрана. Дополнительные изображения открываются, если предыдущие оставили вопрос нерешённым.

Чек-лист ручной проверки остаётся каталогом сценариев для выбора, а не обязательной матрицей просмотра после каждого запуска. Явно заданные пользователем или критериями приёмки визуальные проверки выполняются полностью в указанной области. Фиксированный лимит числа изображений не вводится: он может мешать диагностике, тогда как просмотр всей матрицы создаёт лишние повторы.

### 3. Отчёт отделяет автоматические результаты от визуальных

Исполнитель сообщает, какие экраны, размеры, языки и состояния действительно просмотрены, что найдено и какие существенные ограничения остались. Основной чат может принять этот результат без открытия тех же изображений. Повторный просмотр оправдан изменением отрисовки после интеграции, нерешённым замечанием или запросом пользователя.

Успешный Playwright и существование PNG не считаются подтверждением визуальной проверки. Для обычного успешного прогона без изменений UI достаточно результата автоматических проверок; отдельный визуальный отчёт не требуется.

### 4. Автоматический контур сохраняется

`package.json`, `.githooks/pre-push`, `playwright.config.ts`, `e2e/` и `.github/workflows/` остаются прежними. Альтернативы — удалить создание снимков или перенести все тесты только в CI — не решают непосредственно вопрос повторного анализа изображений и выходят за согласованную область.

## Risks / Trade-offs

- Выборочная проверка может пропустить дефект в другом состоянии → выбирать область по затронутому поведению и выполнять явные критерии приёмки.
- Формулировка об экономии может быть понята как разрешение не проверять изменения UI → сохранить обязанность проверки отрисовки и явно отделить её от полного просмотра артефактов.
- Основной чат может повторить проверку дизайнера по привычке → закрепить достаточность отчёта исполнителя и основания повторного просмотра в маршрутизации.
- Экономия может быть небольшой, если изображения редко открывались → не обещать численное снижение расхода; правило устраняет только лишний просмотр.

## Migration Plan

Согласовать инструкции в одном изменении: общее правило, маршрутизация, процесс и конфигурация дизайнера, затем вводная часть ручного чек-листа. Проверить непротиворечивость на сценариях из `tasks.md`. Исторические отчёты оставить без изменений. Выполнить обязательные проверки доставки по действующим правилам проекта без массового открытия PNG. Изменение начинает действовать для последующих задач после принятия; миграции приложения и данных нет. Откат возможен возвратом правок инструкций.

## Verification

2026-11-03: основной чат и независимый reviewer проверили инструкции чтением, без открытия изображений. Существенных замечаний нет:

- Успешный прогон без изменений UI: `AGENTS.md` и ручной чек-лист не требуют просмотра PNG или визуального отчёта.
- Адаптивное изменение UI: общее правило и процесс дизайнера требуют проверки затронутых экранов и desktop/mobile-размеров.
- Визуальная ошибка: выбор снимков ограничен относящейся к ней областью, дополнительные изображения открываются для нерешённых вопросов.
- Запрос пользователя: заданная область и явные визуальные критерии приёмки выполняются полностью.
- Отчёт исполнителя: маршрутизация разрешает использовать его без повторного открытия снимков, сохраняя ответственность основного чата и основания повторного просмотра.

Историческая запись ручной проверки сохранена; инструкции отделяют её от результатов автоматических запусков. Команды тестов, хуки и CI не изменены.

`git diff --check` и `openspec validate selective-agent-screenshot-review --strict` прошли. Обязательный `E2E_PORT=4293 npm run check` завершился успешно: проверка архитектуры, 247 unit/UI-тестов в 26 файлах, production-сборка и 125 браузерных тестов. Результат подтверждён по текстовому журналу; скриншоты не открывались.
